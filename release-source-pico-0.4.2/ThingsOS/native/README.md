### Reader progress and footer refresh correction (version preserved)

Background indexing processes up to eight pages within a 25 ms budget per UI
iteration (a single font miss or chapter decode can exceed that budget), and
continues when visiting other awake pages. The hinted width cache has 8192 slots;
only actual FreeType loads yield, rather than every 64 cached width lookups.
Before the complete index is available, the footer shows an explicitly approximate
whole-book percentage weighted by uncompressed EPUB spine sizes and decoded
chapter position (TXT uses byte position). Accurate page counts replace the
estimate when indexing completes. It does not claim that HTML size is exact text
or page count. Chapter/index completion is logged for hardware verification.

Ordinary balanced updates use differential GL16 for the body and the official
gray follow waveform for the reader footer. Equal footer pixels remain untouched.
Fast remains binary DU; explicit and periodic cleaning remains full GC16.
Official BSP sources, panel timing and factory VCOM are unchanged. Host tests cover
progress before indexing, indexing across intervening page turns, long TXT
completion and book-close cleanup. Physical refresh appearance requires user
confirmation; startup health alone does not establish it.

### Reader performance and single-line TOC (version preserved)

Opening EPUB reads its navigation document and the restored chapter only; it
does not decompress every spine file to discover headings before the first frame.
Heading fallbacks are collected during normal/background chapter decoding.
Completed page indexes and chapter labels are cached under `/sdcard/.thingsos/`.
The cache key covers all ZIP member CRCs/sizes (or TXT bytes), the full font
content fingerprint, and the layout revision/size/spacing/margins. Bounded,
checksummed cache data is validated before reuse; missing, stale, corrupt or
unwritable caches fall back to incremental indexing. Changes replace the book's
cache instead of accumulating one file per layout. The first calculation remains
necessary for each changed book/font/layout. Background work is capped at 32
pages and a 25 ms budget per iteration; a single chapter decode can exceed it.

A 512-slot gray glyph bitmap cache avoids repeat FreeType rasterization, with
at most 4096 bytes per slot (2 MiB maximum per face). Allocation failure uses the
normal rendering path. Exact cached/original bitmap equivalence is tested.
The TOC shows one row per chapter, title left and starting page right, without
percentages. Unknown starting pages show a dash until indexed. Its right scroll
bar represents the full directory and supports tapping/dragging; chapter opening
does not wait for unindexed chapters elsewhere in the book.
When indexing finishes, an open TOC redraws its starting pages automatically.
Backward chapter changes also reuse the completed part of a still-growing index.

On ESP32, all optional font metric/bitmap tables and bitmap pixels are allocated
exclusively from PSRAM. Small glyph buffers must not use ordinary malloc: the
configured 16 KiB internal-allocation preference otherwise consumes/fragmentates
the internal DMA heap, causing SD reads (book opening and covers) to fail.
No internal-heap fallback is allowed for these caches; unavailable cache memory
uses uncached drawing with identical pixels. Opening logs the largest available
internal DMA block and free PSRAM for device diagnosis.

The reading page no longer has a persistent ThingsOS logo. Opening the reading
menu reveals a large back-to-library control below the status line, at x=24,
y=88 with a 232x88 visual area and a 248x104 touch target. The old status-corner
back action is removed; ordinary reading retains the full body height and the
control is hidden during image viewing. Device-controller tests cover the old
corner, the lowered target, and absence of the persistent reading logo.


### 0.3.1 refresh and device crash correction

Chapter objects in loading and whole-book pagination now live on the heap. The UI component rejects stack frames over 4 KiB at compile time. Settings persist global Balanced (GL16), Fast (binary differential DU), and Clear (GC16) modes, plus a 1/6/12-update cleaning interval and manual full refresh. Balanced is the default. Only first boot performs physical fullclear; regular cleanup draws the target with GC16 once. Continuous updates retain display rails, which turn off after 8 seconds idle. Official full scan timing and factory VCOM remain unchanged. Fast mode quantizes images and antialiased text to black/white.

Reference: https://github.com/MindReset/read_pico_firmware, pinned BSP ed1e9331077451a0391769cd6c191568f7901807; reading waveforms and idle-rail strategy were inspected in main/apps/app_reading.c and main/display.c. Application controllers remain independent. Host checks and real-device acceptance are recorded separately under build/.


### Power key and reader toolbar update (version preserved)

The main UI drains and acknowledges PMU SHORT/LONG key events, enables raw key events when needed, and ignores the boot power-on hold until released. SHORT blanks the panel, disables touch and pauses WiFi, then waits in bounded light sleep; another SHORT restores the same page, menu and reading position. LONG saves records and requests cooperative PMU power-off (REQUEST_OFF / SHUTDOWN_READY). Power-on while EN is low belongs to the PMU and uses its existing key_power_on_ms configuration. No host code runs while powered off. Reading back is visible and actionable only with the reading menu, returning to the library including for the built-in example. Physical PMU shutdown / cold power-on validation requires a connected device. Routine builds retain the current version until an explicit user request to change it.
