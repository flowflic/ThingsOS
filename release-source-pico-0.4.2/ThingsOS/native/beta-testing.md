# ThingsOS 0.3.6-beta.2 · Pico 字体兼容与缺字问题测试

适用：已安装 ThingsOS 0.3.6 的 Read Pico（RDP-G01-W / ESP32-S3）。这是定位阅读缺字的测试版，尚未实机验收。请停止分发 beta.1，使用本包的 beta.2。

## beta.1 更换字体后停在 Font rendering failed 的应急处理

关机后取出 SD 卡，在电脑上备份刚换的字体，并将其改名（例如 `字体.ttf` -> `字体.ttf.disabled`），保留原文件。插回卡开机，原字体路径无法加载时程序会保留内置字体；恢复正常界面后按下方 OTA 步骤安装 beta.2，或刷回原 0.3.6。安装后可以恢复原文件名，再结合日志测试该字体。

`ThingsOS recovery / Font rendering failed` 是 beta.1 主程序主动退出阅读的页面，不能据此认定独立救援程序已运行。若仍无法进入正常界面，请保留屏幕和日志联系维护人员，不对本包应用 bin 做从地址 0 开始的完整 USB 写入。

## 先刷哪个文件

- 测试固件：`ThingsOS-0.3.6-beta.2-…-ota.bin`。
- 结束测试后返回原 0.3.6：`ThingsOS-0.3.6-…-return-ota.bin`。
- `source.zip` 是源码，不用刷。整个测试 ZIP 要先解压，不能作为固件上传。

本包只包含应用 OTA，不改变分区布局，也不升级字体或救援程序。不要把应用 bin 当作从地址 0 写入的完整 USB 镜像。

## 如何刷入（推荐：设备的传书网页）

1. 先记录当前书籍、章节、页码、字体、字号、字重、行距及刷新设置。备份重要阅读记录；升级设计保留 SD 卡书籍和配置，但测试前仍建议备份。
2. 将 SD 卡插在 Pico 中，至少留出 10 MB 可用空间；接好 USB 电源。升级期间保持供电，不拔 SD 卡、不强制关机。
3. 在 Pico 打开“传书”。如果 Pico 已连接家中 Wi-Fi，让手机或电脑也连接同一网络；如使用 Pico 热点，连接传书页面显示的热点并保持此连接。以设备显示的热点信息和局域网地址为准。
4. 在手机或电脑浏览器里打开 Pico“传书”页面显示的 `http://…` 地址。如果页面要求访问令牌，使用设备显示的令牌。这是设备管理网页，不是官网的 USB 安装页。
5. 选择“固件升级”，选择解压后的 `ThingsOS-0.3.6-beta.2-…-ota.bin`，点击“检查固件”。核对项目 `ThingsOS_native`、芯片 `ESP32-S3`、版本 **0.3.6-beta.2**，并与 `SHA256SUMS.txt` 核对 SHA-256。
6. 勾选页面确认项，点击升级按钮。0.3.6 设备网页按钮可能写着“写入备用分区并重启”，但当前布局实际是：先接收到 SD 卡并校验 → 重启进入救援安装程序 → 写入主应用并校验 → 再次重启。中途短暂断网或多次重启属于这一流程；“上传 100%”不代表安装完成。
7. 等设备重新进入界面。在 Pico 的版本信息或重新打开的设备管理网页核对 **0.3.6-beta.2**；若需查看网页，重新进入“传书”，连接页面显示的网络和地址，等待启动健康确认。安装后退出传书，再开始阅读测试。

不要通过“检查在线更新”寻找 beta，本包没有发布到官网。网页在校验前报错时，保留原始报错，不切换到完整擦除安装。

## 怎样测试

优先用原来出现问题的书和字体；先保留原字号、字重、行距、方向、水波纹及刷新模式，避免一开始改变多个变量。

1. 回到反馈时的章节，连续向前翻 30–50 页，期间翻回同一页，观察是否有整字空白、半截字或笔画缺失。
2. 每隔几页停留 1–2 分钟，覆盖状态栏、后台分页或划线加载后的刷新。微读缓存书分别在联网、离线时测试，记录当时网络状态。
3. 测试睡眠后唤醒、退出再进入同一本书。基线测试完成后，再单独切换一次字号或字体，看问题是否与特定设置相关。
4. 再次缺字时，先拍下完整屏幕、记录时间和页码；不要立即重启。然后试翻下一页再返回，记录是否恢复；如果使用的界面提供手动全刷，再记录全刷后是否恢复。若出现 `Font rendering failed`，也拍照并保存日志。

beta.2 会先重建字体，再尝试内置字体；字体仍失败时显示明确的方框并保持界面可操作，失败页不进入预渲染缓存。合成加粗不支持的轮廓保留原始字形，不作为整页失败。FreeType 动态分配改用 PSRAM。有新错误日志、出现临时内置字体提示或成功恢复，都是有价值的测试结果。没有再发生缺字只能说明本轮未复现，不能证明所有原因已排除。

## 可选：Windows 收集诊断日志（强烈建议反馈设备使用）

1. 用 USB 数据线连接 Pico，保持正常阅读模式，不开启“USB 直连模式”。关闭占用串口的其他工具。
2. 在解压目录打开终端，运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\capture-log.ps1
```

3. 按提示填写 Pico 的 COM 口（可在设备管理器“端口”里确认）。脚本只读取 USB 控制台，不发送命令或刷机；成功打开后开始操作设备。
4. 复现后按 Ctrl+C，保留目录中的 `pico-beta-日期时间.log`。默认最多采集 15 分钟。若提示端口占用或找不到设备，记录报错，不用重刷。

日志中的关键字：`Glyph load failed`、`Glyph raster failed`、`Incomplete UI frame`、`Panel draw error`、`Refresh`。日志可能含书名、路径、网络信息及其他个人信息，发送前先检查，只交给本次排查人员。

## 结束测试 / 返回 0.3.6

设备可正常进入传书时，重复上面的升级步骤，选择 `ThingsOS-0.3.6-…-return-ota.bin`；检查出的版本应为 **0.3.6**。当前手动上传入口允许安装这个版本，返回后再次核对版本和阅读功能。这是手动重新安装，不是自动版本回滚。

如果设备停在救援界面，连接救援界面显示的网络和管理地址，在救援网页上传同一个 return-ota.bin。若设备无法进入主界面或救援界面，先联系维护人员并提供当前屏幕/日志；本包不提供完整 USB 擦除镜像。
