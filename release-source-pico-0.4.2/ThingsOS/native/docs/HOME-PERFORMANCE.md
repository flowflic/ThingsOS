# 首页速度与刷新优化

2026-10-13–14，版本保持 0.3.1。实现位于独立 `native/`；官方 BSP、相位长度、屏幕时钟及 VCOM 未改动。最新逐像素保持视图只屏蔽等值像素的驱动动作，变化像素仍执行原官方 GC16 序列；源表未修改。用户授权后通过备用 OTA 槽迭代主应用，镜像及启动选择均读回校验。主机测试、设备运行计时与人眼残影反馈分别记录。

## 已实现

- `display_buffer.c` 用 16×16 块遍历完成固定旋转及 8 bit→4 bit 打包，替代每帧 831,744 次通用像素函数调用。灰阶及单色模式与原始旋转/半字节规则一致。只有该热函数采用 `-O2`；保留尺寸检查与通用转换回退。
- `thumbnail_cache.c` 缓存最终尺寸灰阶缩略图，24 个 LRU 槽、最多 512 KiB，设备仅使用 PSRAM。不同显示尺寸独立缓存；确定缺少封面可以负缓存。读取/解码或缓存分配失败保持回退与重试，不把内存不足误记为没有封面。
- 普通 Tab 返回复用已扫描的书籍列表和 EPUB 标题/作者。卡身份、目录不一致则重新扫描；挂载/移除/重新挂载、换目录、上传完成、文件管理和传书服务关闭等原有扫描路径强制清除缩略图缓存。外部内容变化通过这些事件失效，缓存不是持久化磁盘索引。
- 排序在一轮绘制中复用，书籍数量、ID、阅读顺序或排序模式变化时重算。相同 Tab 且无变化时跳过扫描与提交；已有提示的清除仍能正常绘制。
- 设置保存使用已成功提交的快照去重；只有内容变化才调用 NVS，失败保留未成功状态供下次重试，不使用纯哈希决定持久化是否成功。
- 图片缩放直接写目标行，避免逐个像素调用矩形绘制函数；字体、占位封面及灰阶表现保持原有布局。
- 书库/传书/设置的分钟时间、电量更新只绘制顶部状态栏并做局部打包/提交。到清晰刷新周期时仍使用完整画布；BSP 区域对齐及旧帧基线规则保留。
- 普通首页 GL16 改为一次全像素更新，使官方 `15→15` 白底补偿覆盖未变化的白底。没有增加一帧额外清屏动画。阅读、键盘、开机清屏、错误恢复及既有清晰刷新周期继续沿用原有分支。
- 实机反馈确认提速，但第一版 GL16 页面切换仍有明显上一页残影。因此进一步把实际页面切换、书库排序/视图变化、列表换页和菜单开关改为一次官方 GC16；进入新书也先 GC16。同页一般小变化保留原刷新策略，列表已到边界的无效滑动不再提交。
- 第二轮用户确认残影明显改善，但每次全像素 GC16 过于闪烁。第三轮将切换标记与整屏清理标记分开：切换使用官方差分 GC16，只启用发生变化的行、列；周期清理、开机、唤醒和错误恢复仍执行完整清理。差分范围是行列掩码的交集，不能保证交集内每个未变化像素都不参与波形，也不能消除 GC16 固有闪动。切换计入原清晰刷新周期，避免一直切换而不做完整清理。
- 第四轮尝试首页 DU 擦白→GL16 绘制：黑闪减轻，但用户确认残影明显；因此未保留此分支和临时帧分配。
- 第五轮对书库/传书/设置相互切换采用逐像素保持 GC16 视图。`refresh_mask.c` 将原官方 GC16 的等值 `(from==to)` 动作屏蔽为保持，所有 `(from!=to)` 动作逐相位一致。官方表、相位数、相位时间、温度范围不变，原来的行列差分掩码继续使用。36 相视图只占 2,304 字节静态 LUT，不增加中间帧或 PSRAM 分配。周期/显式/开机/唤醒/错误恢复仍用原表完整清理；初始化不匹配时回退普通差分 GC16。
- 用户追加反馈：打开书籍和长按 HOME 返回仍出现大块黑闪，因为第五轮仅覆盖首页 Tab。第六轮去除该范围限制，将同一保持视图用于全部实际页面切换标记，包括打开书籍、HOME 返回、菜单开关、列表视图变化；周期/显式完整清理优先级保持不变。
- 用户追加要求：正常阅读页底部 `y>=1140` 进度区域只显示信息，点击不打开进度/跳转窗口，不翻页、不触发额外刷新。菜单内显式跳转入口保留。
- 阅读页下方中心电容键短按改为阅读设置菜单开关：一次显示，再次隐藏，可连续切换；运行时覆盖层状态同步，关闭跳转面板，阅读位置不变。两种方向都使用逐像素保持 GC16。长按中心键继续对应 HOME 返回。
- 交互导致的待刷新画面直接提交；后台连续变化仍节流 120 ms，节流时间基准改为上一帧完成时间。初始画面在加载设置后的正确刷新策略下提交，提交成功后清除重复刷新标记。

## 新计时

保留原来的 `UI layout`、`Refresh`、epdiy 的差分/波形/回写日志，新增：

```text
ThingsOS_perf: Library scan: ... ms books=...
ThingsOS_perf: Preferences save: ... ms success=...
ThingsOS_perf: Covers load=... ms decode=... ms scale=... ms loads=... hits=... misses=... cache=... bytes
ThingsOS_perf: Present total=... us power=... temperature=... clear=... pack=... update=... packed=...
ThingsOS_perf: Action id=... page=... before_layout=... ms total=... ms
```

`Covers load` 包括 EPUB 打开、封面读取/解压及关闭等非解码工作；`scale` 包括缩略图缓存生成/绘制及释放。`Present` 分项用微秒记录，包含此前漏计的转换。动作从软件 `tap` 确认开始，不等于真实手指按下或光学稳定时间。

## 验证

- 主机完整测试 8/8。新增全屏 831,744 像素灰阶/单色转换与独立原始旋转规则逐像素一致性检查、状态栏范围外字节保留、边界和非法输入检查。
- 缓存测试覆盖最终尺寸居中/裁剪、尺寸键、负缓存、LRU/容量、分配失败后重试、清除及重新加载。
- 逐像素保持视图测试核对 36×16×16 个动作，变化像素完全保留，等值像素全相位保持；源表与目标边界字节不变，非法容量/空输入/原地修改被拒绝。该主机测试证明构造规则，不证明物理清晰度。
- 真实主控制器测试使用 EPUB 夹具确认首次加载封面，后续绘制和 Tab 返回不再加载；像素结果一致，状态栏绘制不触发封面处理，重复 Tab 不刷新，卡身份变化清除列表/封面。设置未变化跳过提交，提交失败后可重试。
- 主应用及救援应用分别编译；最终镜像、源输入清单、分区容量和依赖边界由 `verify_build.py` 校验，结果见 `build/native-idf/validation.json`。实机结果另记，不能由此推断。

## 实机验收边界

优化前当前设备记录：传书→设置 1,014 ms，返回书库 3,919–3,931 ms，其中书库绘制 2,744–2,760 ms、热供电刷新前准备约 482 ms。见 `build/home-touch-20261013-current.json`。

第一版已运行并通过健康确认：整屏 `pack` 约 56–58 ms，状态栏局部 `pack` 约 3.8 ms；书库重复绘制 47 ms，5 张封面命中缓存。捕获的一次设置→书库切换为 661 ms（含冷供电，恰逢 GC16），与优化前 3,931 ms 的样本相比明显缩短；样本/视图状态有限，不能据此当作严谨的总体统计。用户确认“变快了”，同时明确反馈残影仍明显。

第二轮修正版改用完整 GC16 处理页面/大区域切换，同时移除底部进度点击入口，已编译、通过 8/8 回归并写入另一备用槽。16 次 Tab 样本：书库→传书中位 627 ms（5 次）、传书→设置 598 ms（5 次）、设置→书库 582.5 ms（4 次）；另有两次反向切换。波形提交约 461–464 ms，书库绘制 58–60 ms，刷新前准备约 59–60 ms；冷供电及首次字形加载会增加时间。日志及分段数据见 `build/device-start-home-speed-clean.log` 和 `build/home-speed-clean-device.json`。用户确认“残影明显改善了，底部不再出现进度跳转窗口了”，同时反馈首页 Tab 切换过于闪烁。

第三轮差分 GC16 已通过 8/8 主机回归、主/救援编译及依赖核对，主应用经备用槽写入、完整 SHA-256 读回和启动选择读回后启动；36.9 秒时确认健康。日志 `build/device-start-home-speed-diff.log` 记录 12 次 Tab 动作，普通切换 `clean=0, transition=1`，行列驱动范围约为全屏的 46%–57%，GC16 提交约 444–448 ms；到周期时为 `clean=1`、684×1216 全屏，约 464 ms。用户确认“闪烁明显，残影可接受”，内容区仍整体变黑；仅缩小行列范围不足以解决该体验。

第四轮 DU 擦白→GL16 已编译、写入、确认健康并捕获 16 次 Tab 动作。擦白约 263–265 ms，绘制约 487–489 ms，完整提交约 773 ms；热动作约 0.89–0.94 秒，首次字形/冷供电另加。用户确认“黑闪减轻，但残影明显”，此方案失败，未作为最终实现保留。日志见 `build/device-start-home-speed-smooth.log`。

第五轮逐像素保持 GC16 已完成主/救援编译、8/8 回归、依赖核对，并经备用 `ota_0` 写入、完整 SHA-256 读回及启动记录读回启动；36.9 秒时确认健康。主应用 SHA-256 为 `246285ced3725bde2c3c14cd1be4595c43e1f8a5bf2f674b002699660b53d921`。串口开机地址行有丢失，运行 ELF 身份与已写入镜像匹配，启动槽依据已读回启动记录及唯一镜像身份确认；这一证据边界单独记录。

21 次 Tab 样本中，传书→书库中位 568 ms（5 次）、书库→传书 605.5 ms（4 次）、传书→设置 582 ms（5 次）、设置→传书 612.5 ms（6 次）；另有一次书库→设置首次字形加载 670 ms。普通 GC16 提交约 446–447 ms，书库布局约 60–62 ms，刷新前准备约 59–60 ms。日志确认普通切换 `equal_hold=1`，周期完整清理 `full=1, equal_hold=0`。行列覆盖比例在逐像素保持时仅为驱动范围的上界，不能当作实际参与波形的像素比例。

用户确认首页 Tab“黑闪明显减轻，残影可接受”，保留逐像素保持方案。正常阅读页底部点击仍无跳转/进度弹窗：本轮也记录了底部点击而无对应刷新，主机回归继续覆盖所有底部位置。完整日志见 `build/device-start-home-speed-mask.log`，分段数据见 `build/home-speed-mask-device.json`，各轮镜像、启动健康及用户反馈汇总见 `build/home-speed-device-validation.json`。这属于当前设备和内容的视觉验收，不等于光学稳定时间测量或完整产品资格验证。

第六轮将保持掩码扩展到打开书籍与长按 HOME 返回等全部页面切换，8/8 主机回归、主/救援编译与依赖核对均通过，备用 `ota_1` 写入及全镜像/启动记录读回后启动，36.9 秒确认健康。主应用 SHA-256 为 `5ed77787f6f1e2e64fb529e3d1bdb8ca816cde78141b45d84cfa3d2eb472fc18`。日志 `build/device-start-home-speed-mask-all.log` 确认打开书籍和 HOME 返回均为 `equal_hold=1`，另有一次 HOME 返回恰逢周期 `full=1`；GC16 提交约 461–464 ms。打开不同书籍约 0.91–1.09 秒（含字体布局、持久分页索引读取、冷供电），HOME 动作识别后约 0.64 秒返回，不包含长按识别等待。

用户确认扩展版“黑块闪烁明显减轻，残影可接受”。新增主控制器断言覆盖新书进入和 HOME 返回的切换标记，同时保留唤醒完整刷新断言。

第七轮修复中心键重复短按总是打开设置菜单的问题，改为显示/隐藏切换。8/8 回归、主应用编译和依赖核对已通过，连续两轮菜单开关检查覆盖菜单、运行时覆盖层、刷新标记和阅读位置。备用 `ota_0` 完成主应用 SHA-256 读回及启动记录读回后启动，36.9 秒确认健康；镜像 SHA-256 为 `7b96d1b935d400b648bd88211b6e6a0795ccdb20987fe52177507c03e314f002`。共享显示代码未变化，救援固件沿用第六轮通过编译的版本，未写入救援分区。

用户确认“可以反复显示/隐藏，阅读位置不变”。本轮串口记录连续 4 次中心键短按 `action=2` 及对应 `equal_hold=1` 的菜单切换刷新，日志见 `build/device-start-home-speed-toggle.log`。已验证的首页/开书/HOME 返回闪烁优化与阅读底部进度禁点行为继续保留，版本保持 0.3.1。

首次加载新封面仍需读取/解码；内存不足会回退，不能保证所有冷页都同样快。同步波形期间仍存在输入采样盲区，当前没有重写成非阻塞显示，也没有增加并发设备任务。原有上传/OTA I/O 锁、主任务设备所有权、掉电恢复及阅读保存边界保留。

完整/差分 GC16 的清晰度已通过用户确认，但每次大区域黑闪未通过；DU→GL16 残影也未通过。逐像素保持视图通过首页 Tab、打开书籍与 HOME 返回的用户反馈。周期 GC16 仍会整屏闪一次。此阶段保留固定清晰刷新上限，未改为未经设备验证的自适应清理预算。更多封面、列表/卡片组合以及不同温度下的长期残影仍有待扩大验证。
