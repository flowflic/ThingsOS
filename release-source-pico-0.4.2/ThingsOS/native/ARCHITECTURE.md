# ThingsOS 独立固件架构 · v3

交互基准：`prototypes/thingsOS-v3/ThingsOS-review.html`。
HTML 仅表达需求，应用与解析、排版、联网、OTA 状态机独立编写。

| 模块 | 接入状态 | 验证边界 |
|---|---|---|
| runtime / ui | 位置、书签增删、停表/计时、页面与图像缩放模型 | 主机测试；完整页面尚有缺项 |
| archive / epub | ZIP 流式解压与 CRC，OPF/spine/封面，XHTML 文字和图片锚点 | 测试 EPUB、损坏/越界输入；尚无完整导航/CSS |
| graphics / image_decode | FreeType 真实字宽与抗锯齿，JPEG/PNG 灰阶和透明度 | 主机图文画布；设备峰值待测 |
| thingsos_board | 官方屏幕、触摸、SD、PMU；出厂 VCOM 只读；字体 mmap 校验 | Read Pico 首帧、基本触摸切页、残影清除、SD 挂载、字体校验及 PMU RUNNING 已实测；完整操作验收待做 |
| main | 合并书库、阅读/图片查看/目录/字体、SD 位置保存 | 实际渲染与触摸接线；原型尚未全部完成 |
| thingsos_net | RAM WiFi、热点、浏览器传书和字体上传 | ESP-IDF 编译；网络设备测试待做 |
| update / ota_adapter | 共用失败安全事务，HTTP/PSA/ESP-IDF 写入适配 | 主机模拟断流/写入/哈希/激活失败；硬件断电待测 |
| boot_guard | 自定义 RTC 保留区计数，三次未确认尝试 factory | 计数主机测试、bootloader 链接；复位/断电待测 |
| rescue | 单独 factory 应用，AP/HTTP/OTA 和独立 ASCII 提示 | 实测首帧及 AP/HTTP 服务启动，试运行崩溃后回到 factory；完整网络 OTA 与断电待做 |

显示只在主任务执行。文件读写与 OTA 使用同一个互斥锁；HTTP 忙时主循环停表、
暂停触摸绘制和刷屏。OTA 首段校验芯片与项目标识后才开始写入，全部接收、哈希、
镜像结束检查通过后才调用启动分区选择。factory 和当前运行分区不作为写入目标。正常主应用仅下载和校验 SD 包；提交 NVS 安装意图并选择 factory 后重启。救援主任务在启动 HTTP 前重新核对 SD 大小、项目、版本及 SHA-256，再写主槽，验证完整镜像及 Flash 读回 SHA 后才选择主槽。写入失败保留 factory 选择和安装意图，重启可重试。
SHA-256 提供完整性校验，当前没有签名和来源真实性验证。

字体为用户提供的完整原始 TTF，48 字节头记录魔数、长度和 SHA-256。
首次装载校验后 mmap，FreeType 从映射内存读；SD 字体事务替换，错误保留旧字体。
救援不调用完整字体装载，ASCII 位图随救援应用存在。图片查看位置用章节与源字节
偏移保存，更换字号或关闭图片后保持源位置；之前页面历史在重排后清空。

## 开发分区（16 MiB）

| 分区 | 偏移 | 容量 |
|---|---|---|
| rescue / factory | 0x20000 | 2 MiB |
| ota_0 / 唯一主应用 | 0x220000 | 10.875 MiB |
| system_font | 0xd00000 | 3 MiB |

前部为 NVS/OTA 启动选择元数据/PHY；布局使用全部 16 MiB Flash。唯一内置只读文本为
`Example Test`，用户书籍和字体保存在 SD。字体镜像为 2,978,616 字节，
其中原始完整 TTF 2,978,568 字节，不使用汉字子集。

健康检查需要 BSP、字体与显示成功、触摸控制器成功应答，并稳定运行 30 秒。
仅保留一个主应用，不回退旧版本；若持续早期复位，由主 bootloader RTC
计数在第三次尝试救援。断电会清零易失计数，不能视为无限制断电故障保护。
factory 镜像仍会经过 IDF 检查；损坏时官方引导器的备选搜索不能保证有有效槽。
ROM USB 下载是引导区损坏后的独立恢复路径，需要设备操作实测。

救援共用来源明确的 BSP 和新写 OTA 服务，隔离正常阅读应用与字体/SD 内容故障，
不能隔离共享驱动、WiFi 栈或硬件故障。无 PSRAM 时可跳过显示启动网络，但
供电/PMU、网络缓冲和串口获取凭据必须设备验收。

## 来源和交付边界

只编译 native 源码、固定通用依赖、ESP-IDF 与白名单官方 BSP。
验证脚本检查真实 compile_commands（含主 bootloader）及来源哈希，并记录
主/救援/字体镜像大小、SHA-256、分区一致性和主机测试。
不会把历史实现、哈希相同的共享上游库或未实测硬件结果混为独立实现证明。

版本 0.2.0 是开发标识，未发布。设备键盘、文件浏览、书签及统计持久化已经接入；
实现范围和实机验收项详见
[README.md](README.md)。设备验收和完整安装清单完成前，禁止使用开发烧录目标；
保留历史发布与 Netlify 内容。

## SD 状态与设备交互

`src/input.c` 提供独立 UTF-8 编辑模型与实际设备键盘命中布局；
`src/files.c` 提供限于 SD 的事务式目录扫描与路径导航；
`src/store.c` 提供有界记录、时间归档和带 CRC 的双槽序列化。
`firmware/main/features.inc` 只在主 UI 任务处理渲染、触摸、书签、统计、
WiFi 输入与时间设置。共享 I/O 锁覆盖 SD 保存、扫描及屏幕操作；HTTP 写入时
主任务暂停屏幕和计时。凭据不加入记录文件。

统计将 runtime 的单调计时增量记入当前书籍，日期以有效系统时钟归档。
应用页面退出、书籍切换、书签修改及 30 秒检查点触发保存。数据只在 SD，
不写用户 Flash 文件系统。双槽加载只选择最高有效 generation；保存下一代到
另一槽，并 fsync 后回读校验。CRC 用于意外损坏检测，不作为密码学认证。
有未保存数据时检查卡标识及 generation，避免将原卡记录覆盖新卡。
单槽损坏可恢复；两槽无效时不自动清空原文件。
