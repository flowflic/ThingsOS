# Metalio 晃动翻页：根据 V1 实测日志修复（2026-10-28）

后续完整的左/右现场轨迹已确认 Metalio 安装轴不同于Pico，板层映射已修正，
1113个实测样本回归及34项主机检查通过，已烧录并获用户确认本轮竖屏左右正常、
回正不翻，详见 [安装轴根因](METALIO-TILT-MOUNT.md)。
下文保留前几轮未完整定位时的修正及实机失败证据。

前几轮实机验收未通过：存在漏翻、卡住和方向错乱。第三轮补齐异常样本
处理，并采集完整输入继续定位方向；以下构建、烧录和启动成功均不代表手势已修好。

版本继续使用 `0.0.1-v1-beta`。本次在先前稳定握姿 400ms 初始校准修正上，
处理已经烧录的 V1 在实际使用中暴露的状态恢复问题。

## 证据与代码原因

原始记录在 `build/flash-beta-v1-20261028/motion-serial.log` 和
`tilt-events.jsonl`，分析快照为同目录 `motion-analysis.json`。
用户竖屏测试左右均有漏翻、偶发误翻和几秒后才翻页。

- 样本持续更新，识别事件的采集到主任务时间为 5–240ms，页面刷新为
  431–690ms，不能把全部几秒延迟归因于屏幕扫描。
- 分析快照观察到 22 次重新校准转换。旧代码在跨轴变化超过条件时立即
  清除校准，动作中途也可能触发，随后稳定的动作末端又可能成为零点。
- `calibrated=1 armed=0` 曾持续超过 133 秒，期间角度约 17–19 度。
  旧代码要求回到固定原点的窗口，实际握姿变化后会长期不能再次触发。
- 原始日志只有前 30 条低频原始向量，不能重建完整 25Hz 动作，也不能
  据此确认 Metalio 安装轴方向。本次保持轴映射，增加后续测量证据。

## 修复行为

瞬时跨轴变化保留已有校准，只有改变后的姿势稳定 400ms 才重新定零。
一次已经触发的腕转保持侧倾时不会被捕获为新零点，不会因此连翻。

触发后记录动作方向及峰值。正常回到原握姿稳定 140ms，沿用原零点；
确实反向回转达到门槛、在不同握姿稳定 240ms 后，可以建立新的零点并
恢复触发。触摸后换握姿需要稳定 400ms。仍受原有冷却约束。
稳定判断相对固定锚点，避免缓慢回腕因相邻样本接近而误判为静止。

原零点附近恢复的范围改为各档中立门槛（6/5/3 度），确保严格小于该档的
触发门槛。补充测试复现了高灵敏度旧 8 度回正窗口与 5/7 度触发门槛重叠时的
保持连翻，现已覆盖这项边界。较大偏移通过上述回转后稳定重新定零处理。

初始校准、三档触发门槛、采样率、重力过滤和触摸事件屏蔽继续保留。
正常回腕不再把基线偏移到与原点相差最多 4.5 度的位置。
未改面板波形、字体、电源策略或版本号。

诊断新增校准、就绪、姿势等待、零点、峰值、触发方向、灵敏度、横竖屏、
原始与过滤向量。原始向量维持每 2 秒最多一条，持续输出，不再只输出 30 条；
状态转换单独记录，主任务继续每秒记录检测状态。

## 第三轮：补齐异常样本处理并采集完整输入

异常样本只清除未确认候选和短时加速辅助，不改变原来的就绪状态；已经触发的
周期继续保留方向、峰值及冷却。这样就绪时不会被一个无效样本带入缺少方向的
回正周期，已触发时仍不会因冲击而连续翻页。

方向错乱尚未解决。自动重新定零在现场大幅移动，可能将回正当成反向意图，
需要连续输入及明确的物理动作对应来核对。本轮不凭稀疏日志直接交换传感器轴。
USB连接且每次进入阅读后的前五分钟，逐新样本记录原始三轴、真实毫秒时间、
方向配置、灵敏度、触摸屏蔽、校准/就绪/零点及已触发方向；之后恢复低频诊断。
用户确认动作是屏幕向左右倾斜、手腕转动。
