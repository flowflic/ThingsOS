# Read Pico 启动故障排查 · 2026-10-11

已连接设备的完整 16 MiB Flash 先做只读备份。发布包中启动程序、分区、
OTA 选择、应用、救援和字体逐项哈希一致，排除了下载包损坏或漏写分区。
备份和原始设备日志只保存在 `ThingsOS/build/`，不得加入网站或源码包。

## 已定位问题

1. USB RTS 复位后 ROM 仍报告 DOWNLOAD / waiting for download。
   官方 esptool 的 S3 RTC 看门狗复位可重新启动；普通 USB 复位在此设备上不够。
   网站采用独立 S3 适配器，并绕过安装结束时预先拉住 RTS 的路径。
2. `thingsos_board_start()` 传给官方 PMU 初始化的配置为 NULL。
   官方函数明确返回 ESP_ERR_INVALID_ARG，主应用与救援共享的显示初始化失败。
   改为官方默认配置，并使用带有效参数和 RUNNING 检查的官方就绪助手。
3. 灰阶显示依赖的 data cache line 为 64 字节，旧配置只有 32 字节。
   改为 64 字节 / 64 KiB，Flash 和 PSRAM 仍为 80 MHz。
4. 解决 PMU 后，主应用在第一次标签绘制时 LoadProhibited，地址回溯到
   FreeType `gray_convert_glyph` 绘制之后释放 glyph 位图的堆访问。
   该栅格器的局部池约 16 KiB，大于原主任务 8 KiB 栈，导致越界破坏堆。
   主任务增至 32 KiB并开启编译器栈保护；救援不调用完整字体渲染，保留 8 KiB。

## 修复验证边界

0.2.2 修复触摸与残影：在独立板级封装中按数据包触点数量解析，忽略未使用
触点槽中的旧坐标和 UP 事件；显式复位、唤醒触摸控制器，轮询改为 20 ms。
启动时先清除物理墨水屏保留的旧画面，每六次显示重复清屏，使用全屏灰阶更新。
2026-10-11 用户实机确认触摸正常、残影清除；串口记录了 down/up/tap 与多页面切换。
这项确认仅覆盖当前设备的交互和残影修复，不代表全部功能及断电 OTA 验收完成。

屏下电容键是 CST836U 屏外坐标：硬件指南给出的 y >= 1300、间距 160、
中心 x=80/240/400。自行实现按键状态机，阅读左键上一页、右键下一页、中键
短按调出菜单，按住 1.5 秒返回书库首页。松手不重复触发短按，滑出和多指取消。

主机测试和编译通过不能代替设备验收。故障设备的 ROM USB 下载仍可用，
已观察到应用试运行崩溃后自动启动 factory 救援，AP 与 HTTP 服务启动。
PMU 修复后的设备日志已确认 RUNNING、触摸、SD 挂载和完整内置字体校验。
最终主应用首帧、30 秒健康确认、救援显示及恢复主应用须以设备验证报告为准。
保留 `hardware_qualified=false`，完整 OTA 断电与全部功能验收仍需后续实测。

VCOM 校准。不将未稳定启动的候选固件发布到生产网站。
