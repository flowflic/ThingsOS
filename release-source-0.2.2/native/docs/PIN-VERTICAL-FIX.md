# 密码开关首触与竖排左侧留白修复

## 现场情况与定位边界

用户报告：刚解锁/唤醒后进入电源与锁屏，第一次点击密码开关页面跳动但没有进入，第二次才进入；竖排左侧始终空出约一列。

对已确认的 Metalio 进行了两轮不复位、不烧录的串口采集。用户两轮都确认一次点击正常进入；因此没有捕获到原先失败的现场，不能把这两轮成功表述为原故障已消失。

- 正常路径：`tap x=601 y=618 page=11`，随后 `Navigate from=11 to=29`，PIN 布局 95 ms，整次动作 668 ms。
- 用户按唤醒顺序重试：`tap x=586 y=628 page=11`，随后 `Navigate from=11 to=29`，PIN 布局 70 ms，整次动作 642 ms。
- 两轮没有对应的字体失败或刷新失败，串口已关闭。原始日志仅保留本机 `build/pin-vertical-fix-20261112/input-device.log` 与 `wake-device.log`，不发布。

## 密码开关

代码中确认的触摸丢弃路径：该固定开关原来只在松手分支调用 `tap()`；接触期间移动超过 18 px 后 `moved` 会锁定，松手不会执行点击。其他固定开关已经使用接触即响应的路径，密码开关没有接入。

增加 `power_pin_press()`：首次接触现有开关命中区域就执行原控制器，并设置现有手势的 `held/dragging` 消费标志。后续移动、松手不再取消这次开关操作，也不把同一次接触再次传给新数字键盘。唤醒时一起清理 `held/moved` 状态。模态确认、休眠和命中区域外仍不执行。

没有改读屏、数字键盘或 QWERTY 坐标校准。该修改封闭了可由源码确定的点击丢弃路径；是否完全解决最初那次现场现象，仍需新固件下从唤醒后的首次操作复测。

## 竖排留白

旧排版按固定列距取整，剩余空间可能放得下一个字，却放不下完整列距；最后一列因此被排除。新增回归在旧实现稳定失败，例如字号 30、636 px 正文宽度、175% 行距时，左侧剩余 34 px，超过一字宽。

竖排现在在所选行距附近选择最合适的列数，再按实际正文宽度分配整数列距；竖排使用对称页边距，取消仅针对横排的 12 px 光学右移。横排的行距和位置保持原行为。竖排分页缓存标记由 VRT1 改为 VRT2，使旧索引重新计算，保留原文阅读位置。

## 验证与交付

- 新增 198 组字号（30–70）、边距、行距及横竖屏组合的满宽检查：旧实现失败，修改后通过。
- 原有绘制边界、UTF-8 连续分页、图片/注释、分片恢复和横排像素一致性继续验证。
- PIN 控制器新增唤醒后首次接触即进入、重复接触不触发、命中边界及模态保护回归。
- 完整主机测试、主/救援构建及镜像指纹见 `build/pin-vertical-fix-20261112/validation.json`。布局预览使用测试文本，不是用户书籍的实机照片。

版本保持 0.1.7。本次修复没有烧录或发布；用户设备仍是上次安装的候选。
