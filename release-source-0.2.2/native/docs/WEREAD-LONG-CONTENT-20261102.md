# 微读《惊悚乐园》缓存失败：长正文元数据

日期：2026-11-02；项目：Metalio ESP32-S31；版本保持 0.1.4。

## 复现和根因

两次实机缓存书籍 `491760` 均在 `0/1548` 章失败，界面显示
“正文类型识别：响应格式不兼容，原缓存保留”。目录和 reader 请求成功，
`e_0` HTTP 200、响应 49,239 字节，随后返回 `WD_PROTOCOL=3`。
证据：`build/weidu-jingsong-20261102/capture.log`。

用户开启 USB 直连后，只读复制 `/sdcard/.thingsos/weidu/shard0`。
原响应是合法 JSON，顶层 `bookId=491760`，没有错误码。
`content` 为 17,214 字符、47,482 UTF-8 字节；原通用 JSON 解析器
只允许单字符串最多 4,095 字节。类型识别本不需要保存正文，却因正文过长报错。
原响应 SHA-256：
`7067bd2d972c8c3d127e68eddbe6b130fdedb6358e334d77c95c6c3c37594f12`。
正文保存在忽略的本地 `build/`，不加入源码、测试素材或日志摘要。

## 修复边界

仅在 `e_0` 元数据识别启用既有的有界字符串扫描能力，长 `content`
扫描到末尾并校验转义、Unicode、闭合及 JSON 尾部，不要求整段装入缓冲区。
被截断的正文事件由元数据回调忽略；`bookId` 和错误码仍正常解析，
书籍身份匹配后继续使用既有 `t_0/t_1` 下载和解码流程。
其他认证、书架、目录 JSON 仍使用原来的严格模式。
没有提高通用缓冲上限，没有删除 SD 缓存、会话或旧 EPUB。

本地只读核对的协议参考为
`D:/crossmux/source/lib/WeReadWebApi/src/WeReadClient.cpp` 的
`inspectPrimary`、`FetchPrimary`、`FetchText0/1`：文本元数据识别后同样获取
文本分片。实现保持为 native C，不复制参考实现。

缓存仍在设备运行；本次被动捕获最多 900 秒后自动释放串口，不复位设备。
不得由主机回放、启动健康或首章成功推断整本缓存完成。
