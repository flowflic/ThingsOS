# 设备文件管理：音乐删除与音符图标

2026-10-29，Metalio ESP32-S31，版本保持 `0.0.1-v1-beta`。

## 行为

- 文件管理中的 MP3/WAV 不再点击即播放，而是与书籍一致先弹出操作卡，提供“播放／删除／取消”。删除须再确认，确认或取消后返回原文件目录。
- MP3/WAV 文件使用音乐应用现有音符素材缩放绘制；`music` 目录同样显示音符，仍按文件夹进入，目录不提供删除。
- 有书籍记录的文件沿用暂存重命名、持久化、提交删除的事务与失败恢复；MP3/WAV 和未读书籍没有记录，直接删除目录项，不需要记录库可写。MP3/WAV 扩展名大小写均支持；音频不创建书籍记录，不影响阅读历史。
- 删除正在播放或暂停的同一文件，先等待音频工作线程关闭文件；准备中、停止中、正在录制同一文件或 IMA 上传忙碌时暂缓。不同文件的播放不会被停止。
- 成功后刷新文件目录及已加载的音乐/录音列表，并按当前播放文件重新对齐播放列表索引。
- 共用管理白名单同步允许 MP3/WAV，电脑管理请求也使用同一音频句柄处理后再执行文件事务。

## 删除失败的原因与修复

用户反馈“文件仍在，提示删除失败或不可写”。代码中有两处确定缺陷，均已修复：

- 前置拦截：`management_delete` 把音频删除与阅读记录状态绑在一起，记录库未绑定或阻塞时直接提示 `SD 或记录不可写`。音频不产生书籍记录，删除不需要记录库，因此音频删除现在只要求 SD 可用；书籍删除仍保留该前置条件。
- 静默假成功：`thingsos_book_manage` 在删除最后一步无法移除暂存名时仍返回成功，界面显示已删除，文件却以 `.deleted-*.tmp` 留在卡上。现在移除失败会尝试恢复原名并返回 `THINGSOS_MANAGE_IO`。
- 失败原因现在显示在屏幕上（`management_delete_reason`），入口状态、音频占用、事务返回值与 `errno` 写入 `ThingsOS_manage` 日志。
- 记录库不可写时，删除后不再清除 `records_dirty`，避免未保存的阅读进度被 `management_sync` 丢弃。

尚未取得屏幕上最初的逐字提示，也没有当时是否正在播放的证据，因此旧版本的失败分支仍未在真机区分：音频占用导致暂缓（日志 `delete audio busy`）、SD 卡写入失败（日志 `delete result` 与 `errno`）、记录库写入失败导致回滚。
