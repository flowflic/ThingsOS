## 定位

### 1. VBUS 分类提前否决了真实充电状态

`metalio_power.c` 原先先检查 `VBUS_STAT`：0 或 7 都直接返回未充电，
之后才检查 `CHG_STAT`。但同文件的既有充电初始化关闭了 DPDM。
固定参考源码 `references/metalio-e-ink4-plus/docs/battery-soc-and-charge.md`
第 4.1、5 节明确说明：DPDM 关闭时 `VBUS_STAT` 常为 0，仍可正常充电，
应以充电状态/电池支路电流为准。该参考对应 `upstream-sources.json` 中
Metalio 固定基线 `b400605e9a6a276a2c39864c0cff63798c78e8d8`。

例如 `REG1E=0x08`：CHG_STAT=1（涓流/预充/恒流）、VBUS_STAT=0。
旧逻辑必然返回未充电，使 `thingsos_board_charging()` 为 false，图标无法显示。
新逻辑保留 OTG=7 排除，再优先认可 CHG_STAT=1/2/3，VBUS=0 不再否决它。
CHG_STAT=0 不表示一定已满；保留原有有效适配器分类及电量条件，避免把未充电直接当作充满。

一次读取 REG1E 后同时解码两个字段，避免分两次读到不同瞬时状态。
新增状态变化及 I2C 失败/恢复日志，包含原始寄存器、CHG_STAT、VBUS_STAT 和显示电量；
稳定状态不每 5 秒重复打印。没有改动任何充电控制寄存器写入、VREG、ICHG、终止、再充或欠压保护策略。

### 2. 开机第一分钟的刷新条件错误

原 UI 每 5 秒检测变化后将 `clock_refreshed=0`，再判断
`time-clock_refreshed>60000`。开机不足一分钟时该条件仍为 false，
因此即使检测成功也可能等到第一分钟才刷新。
新代码直接以「充电状态变化或分钟到期」触发刷新，稳定状态保留分钟刷新频率。
界面繁忙时排入包含状态栏的重绘，避免录音进度、键盘等窄刷新范围漏掉顶部变化。
5 秒为主任务正常运行时的轮询周期，不是阻塞操作/休眠期间的硬实时承诺。
