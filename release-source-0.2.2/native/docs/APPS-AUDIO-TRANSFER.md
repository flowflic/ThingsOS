# 应用页音频条目、传输入口与提示横幅

2026-10-29，保持版本 `0.0.1-v1-beta`。

## 原因

音乐页的播放按钮执行暂停，音频服务进入 `PLAY_PAUSED`，保留文件、
播放位置和音频占用以供继续播放。应用页底部条目与传输入口此前均直接
使用 `thingsos_audio_active()`，该函数包含暂停会话，因此暂停后仍显示
“音频播放”，并且无法进入传输。实际停止并由工作任务关闭文件后才会
进入 `IDLE`。

普通提示横幅固定从 y=215 开始绘制，而应用页首排图标从 y=150 开始，
导致横幅覆盖图标下半部。

## 修正

- 应用页仅在正在播放、正在录音或录音暂停时显示底部条目。
  音乐暂停、停止、错误状态均不显示，也不保留对应的点击区域。
  暂停音乐仍可从音乐页恢复。
- 点击传输时重新读取音频服务状态。对已暂停的音乐，调用现有
  `thingsos_audio_quiesce_locked()`，等待文件关闭和占用释放成功后进入。
  失败或未结束均不进入传输。
- 正在播放提示先暂停；录音（含暂停）提示结束并保存；过渡状态提示稍后重试。
  不自动结束未保存录音。
- 应用页普通横幅改为 y=82、高60，底边142，位于 y=150 的首排图标上方。
  保留三秒自动消失与控制中心、其他页面原有提示位置。

## 验证与边界

`device_ui_controller` 使用实际 UI 绘制及点击入口，覆盖：
播放拦截、暂停后释放再传输、缓存状态过期、结束失败与未完成、
录音与暂停录音保护、底部区域清空与点击区域移除。
横幅测试逐像素确认首排图标不受影响，并检查三秒自动消失。
