在不复位设备的情况下捕获两段各 120 秒串口日志，已关闭捕获端口。
用户反馈搜索按钮静置自动加深，并选择《鬼吹灯（盗墓者的经历）》。
本轮捕获跨越多本书的操作，以下耗时不能直接归到该书：

- 一次阅读同步上下文 GET：1,763,945 字节，31,583 ms。
- 一次三章任务：16,135 ms，目录请求 818 ms；三个阅读页分别
  209,878 / 211,193 / 215,309 字节，耗时 3624 / 3886 / 3901 ms。

长上下文同步还会占用唯一微读工作任务，前台加载需等它结束。

## 改动

1. 阅读上下文按需截取：普通章节取得 `psvts` 后停止下载；阅读同步需等
   `psvts`、`pclts`、`token` 三个字段齐全。保持 HTTP 200、TLS、字段/容量检查。
   提前结束的响应关闭并丢弃连接，完整正文响应仍可复用；不把未读完的响应
   拼接到下一个请求。缺字段仍等待原有响应/限制，不伪造成功。
2. 前台章节等待期间不新启动进度/时长同步任务；已发送的云端写操作仍沿用
   原有事务与排队规则。本轮保留“首次三章、后续两章”策略。
3. 章节加载提示从通用 y=215 横幅移到正文上方。等待期间持续显示，避免
   三秒消失导致再刷一帧；成功、取消或手动进入已有章后清除。沉浸阅读临时
   留出 40 px，保留正文，不用提示覆盖正文首行；横屏按实际宽度排版。
4. 搜索动作标记不会再把后续封面/阅读同步完成当作新的搜索完成：搜索完成
   由绑定关键词的状态机处理。封面任务只有真的产生新文件才请求重绘。
   隐藏消息的过期也不再产生无效重绘。
5. 微读及其搜索键盘的分钟时钟/电量更新使用顶部状态条刷新。静置微读页
   在普通刷新前比较真实 4-bit 画面，相同画面跳过扫描。显式全刷、页面切换、
   首帧、策略切换及错误恢复不受此跳过影响；不修改面板 LUT、时序或 VCOM。
