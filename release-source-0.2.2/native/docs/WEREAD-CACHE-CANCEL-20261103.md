# 微读缓存速度、取消响应与长按菜单

日期：2026-11-03；版本保持 0.1.4；基线提交仍为 `db9c837`。
接续 [按章阅读实现](WEREAD-ONLINE-20261102.md)，尚未烧录本候选。

## 交互

短按封面用于阅读；长按封面打开书籍菜单，已缓存和未缓存的书均可使用。
菜单保留划线书评、整本缓存、开始/在线阅读等操作。
整本缓存不是长按后的唯一操作，也不会因长按而直接开始下载。
已有章节源可供继续整本缓存复用，取消仍保留已完成章节及原完整 EPUB。

## 已定位的取消等待

1. `prefetch_stop` 在等待两个预取任务退出时持有显示/SD 全局锁，预取任务可能
   正在等待同一把锁。旧顺序可能形成互相等待；现在先释放锁、等待确认，再恢复
   调用者原有的锁状态，不强制删除任务，也不提前释放共享状态。
2. 缓存路径原先使用阻塞的连接、响应头和正文读取，单步可能等待 15 秒；DNS
   也可能阻塞。现在缓存使用非阻塞 HTTP 状态推进和已有的有界 TLS 传输适配器：
   单次底层等待 1 ms、读取切片约 10 ms，EAGAIN 继续同一请求，不重新发送 POST。
   每次推进检查用户取消和预取停止标记。
3. DNS 在 lwIP 所属任务中发起，等待方轮询取消并有 5 秒整体预算。调用者与 DNS
   回调分别持有引用，取消或超时后的迟到回调仍能安全完成和释放内存。
4. 正文解码、纯文本/HTML 规范化、ZIP 写入、目录生成、逐章校验及 JSON 扫描增加
   分块取消检查。无用的未完成响应不再先执行耐久 fsync；关闭后删除临时响应。
5. 缓存/恢复任务不再跨网络、打包和目录处理持有显示锁；主任务可及时处理取消并
   绘制反馈。重试等待只在调用者确实拥有锁时释放/恢复，并按 tick 检查取消。

HTTP 客户端与自建 TLS transport 成对持有，完整响应后继续复用；失败、取消及
任务结束均由各自所有者清理。公开封面使用独立传输和证书验证，不携带账号头或 Cookie。

新增日志 `Cancel requested action=...` 和 `Cancel cleanup elapsed=... ms`。
后者测量请求取消到网络/存储清理完成的时间，不等同于屏幕完成刷新时间。

## 缓存提速

- JSON 文件解析改为 8 KiB 读取块，避免每个字符调用文件读接口，仍完整检查 JSON
  语法、书籍身份、错误码及字段边界。
- 分片以 16 KiB 块读取，Base64 解码结果以 16 KiB 批量写出，并在块间响应取消。
- 纯文本 XHTML 规范化按连续文字片段批量写入，保留相同的换行、转义和控制字符规则。
- 打包目录表使用 16 KiB 缓冲，减少反复的小量 SD 读取。
- 不跳过章节、不截断正文、不复用未经验证的跨章令牌，也不绕过原内容校验。

## 验证与边界

51/51 主机测试通过，记录于 `build/weidu-cancel-speed-20261103/host-final.log`。
新增/扩展用例覆盖：

- 实际长按/点击控制器：未缓存封面的多操作菜单、显式整本缓存及取消；
- 缓存 HTTP 在等待时响应全局取消、预取停止、超时和终止错误，不重放 POST；
- DNS 成功、失败、排队失败、取消/超时后迟到回调的生命周期；
- 预取退出前释放互斥锁，并等到两个退出确认后才回收；
- 批量纯正文逐字节匹配预期 XHTML，包括跨读取块的中文、转义、换行、CR 和 Tab；
- 规范化、打包和分片解码取消后删除临时产物；原源文件保留；
- 原 1548 章全流程、按章阅读与其他设备控制器回归继续通过。

主固件和救援固件构建通过，日志 `main-final.log`、`rescue-final.log`。
构建验证包含 ESP-IDF 的类型/链接/栈帧检查及主应用 JPEG 符号边界检查。
