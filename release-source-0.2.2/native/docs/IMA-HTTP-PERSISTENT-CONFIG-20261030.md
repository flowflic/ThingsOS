# ima：HTTP 直接配置、持久凭证与验证反馈（2026-10-30）

用户明确选择取消设备解锁密码、在设备保存凭证并在重启后继续使用，且不强制局域网 HTTPS。
版本保持 `0.0.1-v1-beta`。本候选已按用户后续「烧录」授权安装，未发布或提交；前一轮安装证据属于旧的 HTTPS 引导候选。

## 最终行为

- 设备在用户打开「手机配置」期间启动 `http://<局域网 IP>:8081/`，
  二维码直接指向表单，不再启动 8443 HTTPS、自签证书或中间引导页。
- 表单仅包含 8 位设备配对码、Client ID、API Key。没有额外密码或解锁选项。
  仍保留配对服务启动成功才显示二维码、5 分钟有效期、8 次提交尝试上限、
  手动关闭与断网关闭。配对到期会真正停止服务，不自动重新开放。
- 凭证与默认知识库保存在专用 `thingsos-ima` NVS 的 `connection` 记录中，
  启动时自动恢复。版本标记和 SHA-256 仅检测损坏，**不提供加密**。
  设备请求 ima 云端和对象存储的原有 HTTPS 保留。
- 旧 `sealed` 记录需要原密码才能解密，本实现不尝试猜测或绕过；用户重新提交
  Client ID/API Key 后写入新格式并移除旧记录。不读取电脑或浏览器中的凭证。
- 重新配置只有在云端知识库验证成功、NVS 保存成功后才取代旧配置；失败会恢复
  先前连接，清除可能属于新账号的临时知识库列表，保留旧上传目标。
- 「断开 ima」清除专用命名空间中的凭证与同步记录，其他设置、音频不变。

## 配置反馈

旧表单收到 POST 接受响应就结束，设备二维码页又未显示服务消息，导致用户只能
看到「已提交验证，请在设备查看结果」而不知道结果。现 POST 返回 `202 Accepted`
仅表示开始验证，手机继续查询 `/configure/status`，直到实际成功或失败。
查询需要匹配当前配对码的 `X-ThingsOS-Pair-Code` 请求头；响应仅含阶段与消息，
不回传凭证。成功后保留约 15 秒结果查询窗口，随后关闭配对服务。

设备显示独立的验证进度/错误页，失败消息支持换行；可返回二维码或重新打开
已到期的配对。成功后进入默认知识库选择页。手机在失败、断线、超时后清空
API Key 输入框，明确提示检查设备；成功后禁止重复点击提交。
传输错误现在区分 ESP 错误码或 HTTP 状态码，IMA API 的错误消息仍可显示。

## 主机验证与限制

- 凭证测试执行实际存储代码：保存、模拟重启读取、默认知识库更新、写入失败
  保留旧记录、损坏/旧格式拒绝、断开清除。
- 手机脚本测试执行实际表单：无解锁字段、提交 payload 不含密码、验证中到成功、
  验证失败、配对码拒绝、配对到期、断线、最长等待界限和 API Key 清除。
- UI 回归覆盖验证进度、失败消息、返回二维码、到期后重新配对、成功跳转与
  配对期间防止自动休眠；预览在 `build/native-fixtures/ima-simple-layout.png`。
- 测试与构建日志：`build/ima-simple-host-tests.log`、
  `build/ima-simple-firmware-build.log`。

尚未取得此候选的设备 HTTP 配置、真实云端凭证验证、掉电重启恢复或实际上传证据。
