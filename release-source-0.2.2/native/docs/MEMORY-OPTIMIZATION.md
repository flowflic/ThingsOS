# Metalio 第一批内部RAM回收：初始化工作区和上传缓冲

2026-10-29，按用户指定先优化内存审计中的第1、2项。版本保持 `0.0.1-v1-beta`。
候选准备阶段未刷机；随后用户明确授权安装，设备证据见末节。
本地候选保留此前准备的SD DMA预留修复，以及新的两项内存回收。

## 设备RAM数量与33KiB的意义

本地S31 SDK映射的通用内部SRAM范围 `0x2f000000–0x2f080000` 为512KiB，
另有32KiB低功耗SRAM。设备启动实测外部PSRAM为16MiB；Flash另为16MiB。
低功耗RAM与内部SRAM能力不同，PSRAM也不能直接代替内部任务栈、ISR及DMA缓冲。

最近已安装版本的书库阶段内部空闲为87.5KiB，最大连续块约50KiB；开书后分别
约83.4KiB、48KiB。该启动阶段低水位约35.2KiB。之后音频播放实际出现DMA申请失败，
但没有该瞬间完整堆快照，不能把启动数值当作当前播放余量。

33KiB占512KiB通用内部SRAM的6.4%，相对87.5KiB书库空闲约37.7%。
因此这是对紧张内部池有意义的第一批回收。前一轮SD修复还会预留最多8KiB DMA缓冲，
与当前已安装版本相比不能承诺运行时净增完整33KiB，必须按相同阶段再采集。

大头包括内部常驻代码约110.2KiB、显示行数据队列约76KiB、24KiB主任务栈、
音频期间32KiB任务栈和约12KiB I2S DMA载荷，以及网络任务和驱动缓冲。
这些不是可直接搬到PSRAM的等价数据。进一步回收应在工作区、栈高水位和外设共存
验证后逐项实施，保持已验收的面板供数时序与36相校正。

## 修改

### 波形初始化工作区

原始参考代码中的 `static trimmed_seq_t seqs[16][16]` 为17,408字节。
采用与Pico FreeType工作区迁移相同的构建期副本方案：

- `patch_waveform_workspace.py` 严格核对原文件SHA-256，在build目录生成副本，保留上游SPDX。
- 工作区仅在裁剪初始化时分配，成功及相数超限返回前释放，不再成为内部静态对象。
- 主应用只从PSRAM申请，不用内部RAM兜底。
- 救援在PSRAM未初始化时允许临时内部RAM分配，完成后释放，保留无PSRAM恢复路径。
- 波形算法、输出相数、每阶段动作及尾部保持顺序保持原样。

参考checkout未修改。主应用、救援的编译清单均只包含一份生成后的裁剪单元。

### 上传接收块

原16,384字节静态接收块改为严格从PSRAM按次分配，容量仍16KiB。
申请失败在创建临时文件、接收请求体之前返回503，不回退内部RAM。
流式接收循环结束立即释放，之后才做文件同步与提交；取消、读写错误、SD移除及
文件打开失败同样释放。HTTP处理函数提取到 `thingsos_net/upload.inc`，供实际函数回归。
原32KiB文件缓冲、上传分段计时、原子提交和旧文件保护流程继续保留。
