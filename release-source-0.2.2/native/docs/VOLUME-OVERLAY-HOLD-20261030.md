# 音量浮层快按时反复隐藏：计时修复（2026-10-30）

版本保持 `0.0.1-v1-beta`。本轮仅修改主任务 UI 的音量浮层计时；
未改音量步长、音频输出、阅读页按键语义、板级按键扫描或波形。
后续已按用户 2026-10-31「烧录」授权安装本候选；未发布或提交。设备连续按键体验仍待用户复测。

## 根因

原 `app_volume_set()` 先设 `now()+1600`，然后同步保存 NVS，排版与面板刷新
也在该期限内进行。正常 UI 刷新本身就可能花费数百毫秒，慢帧/重试更长，
因此用户看到浮层时，1.6 秒期限可能已消耗大半。绘制时又按当前时间判断
是否显示，过期轮询则排入隐藏帧。连续按键与主任务刷新交错时便可能
出现收起后又弹出的现象。

这里是可直接由源码确认的计时缺陷，不等同于已测量用户每次按键的实际延迟。
本轮也不声称修复硬件扫描在刷新期间可能漏采的短按事件。

## 修改

- 时长改为 3 秒，先完成原有音量设置保存，再设置临时绘制期限。
- 新音量有待显示时，浮层绘制/过期判断保留它，避免慢排版使其提前消失。
- 只有包含新浮层的帧呈现成功后，才开始完整 3 秒空闲倒计时；失败帧继续等待。
- 连续调节（含 0/100 边界处再次按键）会重新标记待显示并延长最终显示期限。
- 普通音频进度或页面重绘不会重复延长，停止调节后仍能按时消失。
- 控制中心内不等待一个被隐藏的全局浮层；休眠/关机清除暂态显示，避免
  唤醒后弹出旧音量条。显示与计时仍由主任务负责。
