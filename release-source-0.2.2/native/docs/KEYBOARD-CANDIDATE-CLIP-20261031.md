# 键盘误触邻近按键与中文候选/拼音显示不完整

日期：2026-10-31
目标板：Metalio E-Ink4-Plus（ESP32-S31）
版本：0.1.0（按用户版本策略，本次为常规修复，未改版本号）
状态：**仅宿主机验证 + 固件编译通过；未烧录设备**

## 现象

用户在使用 Wi-Fi/搜书输入法的屏上键盘（中文输入法开启）时报告三个问题：

1. 键盘输入容易出现错位误触相邻按键。
2. 中文下中文联想的字显示不完整，下半部分缺失一块。
3. 拼音以及拼写也不完整。

## 结论

三个现象对应**三处独立的缺陷**，不是同一个原因。

### 一、误触相邻按键 —— 命中矩形与绘制矩形不是同一个

`native/firmware/main/network_ui.inc` 里 `wifi_key_hit()` 与 `input_key_border()`
本应共享同一套键帽几何，实际却有三处分叉：

| 位置 | 绘制 | 旧命中测试 | 后果 |
| --- | --- | --- | --- |
| 底排高度 | 68 px（`input_key_border` 固定画 68 行） | 90 px | 空格/中英/下一步下方 22 px 空白条会打出按键 |
| 左右外框 | 28..656 | 先把 x 夹到 28..655 再选最近中心 | 空格左侧、方向键右侧出现"不是手指下面的键" |
| 缝隙归属 | 列间 6 px、行间 14 px 留白 | 按**按键中心**取最近，跨行比较 | 空格右端 8 px 打成"中 / 英"，"中 / 英"左端 1 px 打回空格 |

关键点是第三行：旧实现按"谁的中心更近"决定归属。空格（x 200..440，中心 320）
和"中 / 英"（x 448..524，中心 486）之间，落点 x=440..447 明明还在空格矩形内，
但距"中 / 英"中心更近，于是打出旁边的键——这就是用户说的"错位误触相邻按键"。

修复方式：先判断落点是否落在某个**已绘制**键帽矩形内，是则直接返回该键；
只有落在缝隙里才启用就近回退，且回退分两步——先按绘制带选行，再在**该行内**
按边缘距离选键。行内比较使宽键（空格、下一步）不会抢走已经落在窄键内部
的落点，跨行比较被禁止使 Shift/删除键不会吃到字母行的点按。

### 二、中文联想候选缺下半部分 —— 候选行字号按字数各自缩放

旧代码对候选逐列决定字号：

```c
keyboard_label(candidate, 36+i*204, 736, strlen(candidate)>18?22:28, 196, true);
```

超过 18 字节的词单独缩到 22 px，同页其他候选仍是 28 px。`词语联想` 这类联想
词长度不一，于是一行里出现三种字高，偏小的那个看起来就像"字的下半部分缺了一块"。
实测设备照片（`build/attached-20261031/b.png`）中三个候选的墨迹高度确实不同，
但每个字的上下抗锯齿过渡都完整——所以不是渲染裁剪，而是**同行字号不一致**。

同时该行的基线是 736，而键盘在 746 起会先清一块白再重画（`thingsos_rect(28,746,628,330,255)`）。
候选行底部离那条 erase 边只有 9 px；`ui_size_percent` 最大到 113%（`thingsos_font_size`
把 28 px 放大到 31 px）时下缘可以贴到边上，裕量本来就不安全。

修复方式：

- 候选行改成**整行一个字号**：先测量本页三个候选，取能让三列全部放进 196 px
  的最大档（28/26/24/22/20/18），三列同字号同基线。
- 候选基线 736 → 730，计数行 664 → 660，拼音行 694 → 692，让整块候选区上移，
  与 746 之间留出 15 px 净空。

### 三、拼音不完整 —— 按字节截断

旧代码截的是**字节数**：

```c
const char* visible = app.input.composition + (composed>26 ? composed-26 : 0);
```

`THINGSOS_IME_COMPOSITION_LIMIT` 是 64，长拼音会被砍到只剩尾部 26 字节，
既丢掉了行内其实放得下的内容，又可能把多字节字符从中间切开，
渲染成替换符——这就是"拼音以及拼写也不完整"。

修复方式：改成按字符测量截尾（`input_text_tail()`），只保留整字符，
并真正用满 `INPUT_COMPOSITION_WIDTH`(458 px) 的宽度，超出才加省略号。

### 四、顺带修掉的重复几何

候选点选区与翻页箭头的命中矩形原先在 `features.inc` 和 `main.c`
（`keyboard_mode_press`）里各写一份，且与绘制不完全一致（候选区写作 704..752，
比实际绘制的候选行低 2 行，压到了键盘区）。现在统一为 `network_ui.inc` 里的
`input_hit_candidate()` / `input_hit_page()` / `input_candidate_index()`，
绘制与命中引用同一组常量。
