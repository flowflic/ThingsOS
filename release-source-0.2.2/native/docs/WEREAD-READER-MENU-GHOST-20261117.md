# 微读加载后阅读菜单残影：低闪修复

## 现象与代码定位

用户实拍：新章节在线加载完成后立即打开阅读设置，菜单白底残留正文；翻几页后再打开消失。照片可确认残影，不能独立证明面板的具体驱动过程。

源代码确认了白底维护被跳过的缺口：

- `online_modal_draw()` 把加载卡片以外的正文混成浅灰色；退出时 `online.cleanup` 让目标阅读页走加载专用输出。
- `loading_present()` 原先对完整画布调用差分 `epd_hl_update_area(..., MODE_GL16, ...)`。其差分掩码跳过软件值未变的白像素，即使这些位置还留有实际墨迹。
- `e0470_epaper_waveform.c` 的 `e0470_gl16_white_tick()` 已在现有 GL16 相位内加入一次白底维护，源码明确要求全像素传递才能作用于未变白底。调用差分接口使这个保护失效。
- 阅读设置走 `reader_ui` 路径，`thingsos_refresh_automatic_clean()` 会延后自动清理；因此菜单可能继续保留已有残影。后续普通翻页的全像素白底维护可解释残影逐渐消失，但本轮没有采集面板光学或扫描日志来直接证实该过程。

## 最终修复

完整加载画布改用 `epd_hl_update_area_full(..., MODE_GL16, ...)`：把现有 GL16 波形传给区域内所有像素，使未变白底也收到维护脉冲。这里的 `full` 指像素覆盖范围，不是切换为 GC16 完整灰阶清理。

不增加扫描次数或相位；不请求 `thingsos_board_full_refresh()`；加载卡片和状态栏保留原区域范围，转圈保留 64×66 DU 差分。继续沿用加载安全时钟、错误恢复及失败后保留 `online.cleanup` 的机制。横竖屏均覆盖。

按用户要求，`AGENTS.md` 已记录优先低闪、尽量避免完整灰阶刷新，同时保留必要安全清理的偏好。版本保持 0.2.0。代码修改阶段未刷机；随后授权安装见下文。本次未提交、未发布；没有改动参考仓库、VCOM、充电策略或 Pico 源树。

证据目录：`build/reader-menu-ghost-20261117/`。

- `lowflash-regression-before.log`：将原完整画布差分调用代入新测试，首个 GL16 全像素维护断言失败，证明测试能识别原缺口。

- `firmware-build-final.log`：最终主固件构建与 JPEG 链接检查通过，产物与哈希见同目录 `validation.json`。

主机验证不能证明墨水屏实际残影已消失。需要真机重复“等待未缓存章节 → 立即打开阅读设置”，并检查横屏、取消/重试、连续跨章及菜单关闭后的观感。正常加载退出不应出现新增的 GC16 黑白清理；实际消影强度及平滑程度以设备验收为准。
