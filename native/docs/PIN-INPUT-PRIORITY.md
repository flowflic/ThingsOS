# 首次点击先刷旧页、延迟出现数字键盘（2026-11-13）

## 本轮实际捕获

用户在已烧录 0.1.7（应用 SHA-256 `7471d2a27cebabbfabed82908d40f259038ad8b0ff3970bc97a5f898e0a7eb31`）后，报告点击关闭解锁密码只闪一下、没有键盘。随后确认保持原样、没有再次触摸时，键盘延迟出现。

之前误选的“这次弹出验证键盘了”已由用户明确撤回，不作为证据。

同一次操作只有一组接触，坐标 `631,638`，在修复后的整行命中范围内。时序如下（设备启动后毫秒）：

| 事件 | 时刻 |
| --- | ---: |
| 原设置页后台布局开始（按布局耗时反推） | 361902 |
| 触摸 DOWN | 361905 |
| 触摸 UP | 361936 |
| 原设置页布局完成 | 361953 |
| 原设置页 GC16 扫描完成 | 362524 |
| 同一次点击开始分发 | 362529 |
| POWER → LOCK_PIN 导航 | 362530 |
| 数字键盘显示完成 | 363177 |

根因：触摸在 `draw()` 期间进入采样队列；主循环只在布局前取一次输入，布局后未重新检查队列，因而先扫描了已无必要的后台设置页，再分发点击、绘制 PIN。多了一次约 570 ms 的旧页更新，整次按下到键盘显示约 1272 ms。该现场证明的是延迟路径，不能把此前所有无日志的历史报告都认定为相同根因。

原始日志及结构化时序：`build/pin-keypad-refresh-20261113/usb-install-20261113/post-flash/disable-reenable/`。采集串口已关闭。PIN 输入坐标仍受隐私保护。

## 修复

主循环在后台布局前与布局完成后、扫描前，两次检查触摸队列。有未分发输入且本帧并非已接受用户动作时，保留 dirty/强制刷新/过渡标志，释放 I/O 锁，优先进入下一轮处理输入。避免先提交旧场景。

已经接受的 contact 动作仍可在 UP 留在队列时立即显示，保留此前 PIN/首页固定开关的接触即响应。不会取消正在进行的面板扫描，也不让多个任务并发访问屏幕。

新增回归使用上述真实 DOWN/UP 时序、真实触摸队列及密码控制器，验证：物理接触已结束仍需处理队列；后台帧让路且刷新标志不丢失；一次开关接触导航 PIN；等待中的 UP 不阻止前台键盘刷新、不重复输入数字。

控制器回归通过。主固件构建和设备安装/复测状态记录在本机 `build/pin-input-priority-20261113/`。版本保持 0.1.7；本文件初写时尚在构建，不能据此宣称该修复已实机验收。
