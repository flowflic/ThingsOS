# 微读阅读缓冲、搜索与加入书架（2026-11-03）

项目：Metalio `D:\ThingsOS_nologotech`，保持 0.1.5，本地后续修复。

## 问题与行为

- 初次打开只等待当前章，后台预取还受最后活动后 1 秒门槛限制，每个工作任务只取一章并关闭连接。封面和版权等短章容易读到缓存边缘。
- 现为联网打开先准备当前位置及后两章；阅读中立即补齐后两章。每个任务最多三章，批次内复用网络连接，已有章节不重复下载，到书尾收窄范围。
- 请求目标落在正在下载的范围内时继续该任务，范围外才取消并切换目标；已完成章节通过原子文件发布，前台可在批次完成前读取已就绪目标。
- 无网络时仍允许打开已有当前章。前置缓冲失败但当前章已就绪时允许继续；用户取消不自动打开。陌生章节的实际请求延迟仍受网络和服务响应影响。
- 搜索原来启动请求后未立即取回忙碌状态，因此本地无匹配会先显示“未找到”。现在搜索有独立且绑定关键词的等待/完成/失败状态，等待其他后台任务时同样显示搜索中；失败不会伪装成空结果。
- 搜索结果优先显示书架匹配，在线结果按 ID 去重；结果行标注书架/在线来源。未在书架的在线书籍短按打开操作页，可选择加入书架、在线阅读、整本缓存、划线书评。书架内的短按阅读和长按多操作菜单保留。
- 服务端确认加入成功后原子更新账号绑定的本地书架；菜单显示“已在书架”，重复点击不发送请求。返回保留搜索关键词；离开搜索后迟到结果不会重新打开搜索。

## 加入书架接口依据

只读核对 [微信读书官方阅读页](https://weread.qq.com/web/reader/a57325c05c8ed3a57224187)
引用的 [官方公开脚本](https://cdn.weread.qq.com/web/wrwebnjlogic/js/app.d51b45eb.js)：
`POST /web/shelf/add`，JSON `bookIds` 数组，成功判断 `succ == 1`。
未从其他固件复制实现。网络失败、拒绝或缺少成功标记时不更新本地书架；
云端确认但本地写入失败时明确提示点击同步，不伪称本地更新成功。

## 搜索页麻点

代码核对发现阅读页已立即断轨，但微读页及其搜索键盘仍保留刷新后 3 秒电源复用窗口。
现让微读页和从微读进入的键盘页在成功刷新后立即关闭显示电源，并执行原有输出/偏置关断校验；
使用原厂既有断轨流程，不修改波形、时序、VCOM 或充电策略。

这属于基于已验证阅读策略的针对性修复，尚不能证明此次麻点只有该原因。
旧固件的 25 秒无复位被动串口捕获为空，未取得此次光学现象的直接硬件日志。
搜索结果页和搜索键盘分别静置至少 3 分钟仍需实机验收。
