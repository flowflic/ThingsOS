# ima 配对布局与扫码引导修复（2026-10-30）

版本保持 `0.0.1-v1-beta`。后续按用户「烧录」授权安装，未发布或提交代码。

## 现场与判断边界

本轮用户照片显示真实的 8 位配对码与 194 秒倒计时。因此不能继续用
「配对服务未启动」解释本次打不开网页。照片中最后一行指纹与浏览器提示
直接重叠；页面第一行说明的基线原为 212，而标题分隔线在 210，间距也不足。

旧二维码直接指向临时自签证书的 `https://<设备 IP>:8443/`，扫码工具可能
拒绝证书或不提供继续入口。电脑对照片中旧地址的只读 TCP 探测超时，未获得
TLS/HTTP 响应；这不能区分休眠、配对已过期、局域网隔离或服务故障。
本轮不能宣称已定位手机连接失败的唯一根因。

## 修改

- 主屏按标题、同 WiFi 提示、300 px 二维码、地址、配对码、剩余时间、
  指纹入口、关闭按钮排列，全部内容在底部导航以上。
- 完整 32 字节 SHA-256 指纹单独显示，四行间距 50 px；返回键先返回二维码，
  不关闭当前配对。与新的手机表单说明保持一致。
- 二维码改为 `http://<设备 IP>:8081/`。此入口仅返回静态引导页，没有表单、
  凭证接口或自动提交；页面明确提示在系统浏览器继续，点击后进入原 HTTPS
  配置页。配对码、Client ID、API Key、密码仍只由 HTTPS `/configure` 接收。
- HTTPS 与扫码引导服务均启动成功才公布二维码。关闭、过期、WiFi 断开会
  回收两个服务及临时证书；引导服务启动失败会同时回收 HTTPS，避免半启动。
- 配对有效期间禁止自动休眠，手动电源操作保留原有关闭网络流程。
  超时/失败页面提供「重新打开手机配对」。
- 主固件 socket 上限 10 → 16，为已有传输 HTTP、配对 HTTPS、新引导服务
  的监听/控制 socket、浏览器连接及 DNS/API 留出空间；救援配置不变。
- 修正倒计时读取两次时钟可能跨越过期边界而无符号下溢的问题。
