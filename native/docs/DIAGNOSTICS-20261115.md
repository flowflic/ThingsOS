# 用户异常诊断日志（2026-11-15）

入口：设置 → 日志 → 导出诊断包。开启设备的传输网页后点击「下载诊断包」，
下载 `ThingsOS-diagnostics.json`。独立急救网页提供同一入口；急救访问仍需设备访问码。
正常系统沿用本地传输服务的访问策略。没有互联网也可从本地设备网页下载。

本次保持 `native/VERSION` 的 0.1.8，不修改分区布局、boot guard 阈值、启动健康条件、
充电策略或刷机门禁。未烧录、未发布。急救功能需要同时部署包含本功能的急救镜像；
只更新主固件不会使已经安装的旧急救网页自动获得日志功能。

## 存储规则

- **SD 已挂载**：完整结构化诊断记录只保存在
  `/sdcard/.thingsos-diagnostics/events-0.bin` 和 `events-1.bin`。
  两份 CRC 校验快照交替写入，保留上一份有效快照；每份容量固定为
  `sizeof(thingsos_diag_journal_t)`，不会随使用时间增长。
  最多保留 4 次启动、64 条近期事件，以及独立保留的最近主程序身份。
  （2026-11-20 起为格式 2：512 条近期事件 + 独立的 64 条失败事件环，见文末。）
  「完整」指这里描述的全部诊断字段，并非无限期历史或任意串口输出。
  事件先写 RAM，变化时每 30 秒批量写卡；健康确认、待机前、主动急救和升级转换强制检查点。
- **无卡或挂载失败**：Flash 的独立 NVS 命名空间 `thingsos-diag` 仅保存
  小型核心摘要：启动历史、最近主程序身份、待进入急救的原因、最后事件和最后错误。
  不保存完整事件环，不改其他命名空间。变化时至多每 5 分钟检查点；健康确认、
  主动急救和更新转换可立即保存，同一代数据不重复写入。
- **SD 正在初始化**：不提前回退到 Flash；暂存在 RAM / RTC 保留区。
- RTC 保留区保存核心摘要，应对普通软件/看门狗复位；它不是 Flash，不保证断电保留。
  掉电时只能恢复最近一次有效持久化快照，尚未批量提交的事件可能丢失。
- SD 已挂载但诊断写入失败时记录保存错误，不偷偷把完整事件转写 Flash。
  CRC 拒绝损坏快照，读取两份中最新的有效记录。

SD / NVS 写入在正常任务上下文进行，不在 panic 或中断上下文写文件。
周期 SD 保存由持有共享 I/O 锁的 UI 任务调用，排除 USB 直连和 OTA 写入阶段；
安装器在独占 SD / Flash 阶段保存转换记录。网页导出读取 RAM 快照，不争用 SD。
不截获自由文本串口日志，避免现有串口输出中的路径、书名或账号字段进入诊断包。

## 字段说明

`boots` 是启动历史；`last_main` 即使被多次急救启动挤出历史环也单独保留。
字段包含启动编号、固件版本、完整 ELF SHA-256、运行和选定分区、复位原因数值、
boot guard 启动尝试次数、健康确认状态和急救原因。

急救原因：0 未记录，1 连续启动未确认，2 手动进入，3 固件更新安装，4 更新安装失败。
boot guard 触发从实际 RTC guard 的 magic / complement / attempts 验证后判断，
不靠用户描述推断。急救面板内置 ASCII 字体显示对应英文，网页显示中文原因。
旧固件没有记录时显示「原因未记录」，不伪造故障结论。

`events` 每条含 `boot`、启动后毫秒 `ms`、UTC 秒 `utc`（未校时时为 0）、
`kind`、`stage`、`a`、`b`、`code`、`errno`。
最后一个字段是通用底层错误数值槽；网络 TLS 和请求阶段记录会按下表复用，
只有明确标注 socket / filesystem errno 的记录才解释为 errno。

| kind | 内容 | stage / a / b / code / errno |
|---|---|---|
| 1 | 启动 | 复位原因 / guard 尝试次数 |
| 2 | 健康确认 | 对应 boot 的 healthy 同时更新 |
| 3 | 页面切换 | a 原页面枚举，b 请求页面枚举；不含触摸坐标或输入内容 |
| 4 | 待机 | stage 0 请求挂起；a 电量，b 充电状态 |
| 5 | 唤醒 | stage 0 UI 恢复；stage 1 实际 light sleep 返回；a 唤醒源位图，code 返回码 |
| 6 | 电源 | 关机请求 |
| 7 | 任务 | stage 1 微读状态转换；2 微读请求最终业务结果；3 音频状态和错误码 |
| 8 | EPUB 转换 | stage 0：a 从 0 开始的条目索引，b 显示章号；失败阶段：a 输入位置，b 输入大小，code 输出位置，errno 文件错误 |
| 9 | 急救转换 | stage 急救原因，code 返回码 |
| 10 | 安装 | stage 1 开始，2 结束；a 已处理字节，b 总量，code ESP 错误 |
| 11 | 错误摘要 | stage 1 主程序初始化/显示回退，2 请求故障，3 下载最终故障，4 SD 诊断保存故障，5 屏幕扫描失败原因，6 安全时钟恢复重绘仍失败的原因（5/6 编码见文末） |
| 12 | WiFi | stage 0 连接尝试，1 已关联等 DHCP，2 获取 IP，3 断开（a 原因码），4 请求前状态（a 请求编号，b 任务，code RSSI，errno AP 查询返回码），5 连接/DHCP 等待耗尽 |
| 13 | DNS | stage 接口类别，a 请求编号（图片为跳转次数），code WD 结果 |
| 14 | HTTP | stage 接口类别，a 请求编号（图片为跳转次数），b HTTP 状态，code ESP 请求结果，errno socket errno |
| 15 | TLS | stage 接口类别，a 请求编号，b 校验 flags，code TLS 错误，errno TLS/transport ESP 错误 |
| 16 | 请求统计 | stage 接口类别，a 请求编号，b 接收字节，code 耗时毫秒，errno 请求内部阶段 |
| 17 | 重试 | a 本次尝试序号，b 尝试上限，code WD 结果 |

接口类别：0 其他/授权，1 章节分片，2 reader 页，3 目录，4 书架，5 搜索，
6 公众号，7 时长上传，8 阅读进度，9 笔记网关，10 公共图片。
请求编号在每次启动内有效，结合 boot / ms 关联并发请求。
不保存 URL、查询词、主机 IP、SSID、MAC、Cookie、令牌、正文或响应内容。
网络失败应同时查看最终 WD 结果、HTTP 状态、TLS 数值、DNS 结果和断线记录，
不能把 HTTP 200 或 WiFi 已关联单独当成下载完整成功。

EPUB 失败阶段：1 打开输入，2 打开输出，3 分配内存，4 写输出，5 标签扫描到 EOF，
6 非法数字实体，7 输入读取，8 flush，9 close，10 章节容量，11 取消，12 跳过区域未闭合。
界面同时显示更具体的 `normalize-open-input`、`normalize-tag-eof`、
`normalize-entity`、`normalize-flush` 等原因。原始文件仍由用户单独选择提供；
诊断包不会自动附带原文。

## 格式 2：容量与屏幕扫描失败原因（2026-11-20）

- 诊断记录放在 PSRAM（`EXT_RAM_BSS_ATTR`），由互斥锁保护，不占内部/DMA SRAM；原 64 条版本约 3 KB 位于内部 SRAM，已释放。常驻约 21 KB；导出与 SD 保存临时复制一份，SD 合并时临时两份，均在 PSRAM。
- 普通事件 512 条；另有 64 条失败事件环（kind 11，自动去重），网络事件再多也不会把失败挤掉。导出 JSON `schema` 为 2，新增 `failures` 数组；近期失败也会同时出现在 `events` 中，按 boot/ms 排序即可。
- 格式魔数改为 `0x44494132`。旧版 SD 快照因大小/CRC 不符被拒绝，升级后首次开机不继承旧格式历史；急救 0.1.8 读不懂新格式，不会误读。
- 屏幕失败在原 stage 1 事件之后追加 stage 5（恢复重绘仍失败时 stage 6）：
  - `a`：原因位：1 DMA 完成描述符不在补齐窗口，2 GDMA 描述符错误，4 CKV 计数，8 供数线程发现队列被取空，16 供数队列满 1 秒，32 预填前缀未提交，64 LCD 帧超时，128 供数线程超时，256 LCD 外设硬件欠载，32768 其他。
  - `b`：本次刷新中最长的完成中断间隔（µs）；20 MHz 下一个 8 行缓冲为 136 µs，三缓冲可容忍到约 408 µs。
  - `code`：`相位 << 16 | 本相位已发送行数`。
  - `errno`：`补齐次数 << 16 | 最长中断处理时间（µs）`。
