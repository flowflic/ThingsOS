# 本次开机扫描欠载统计

用户要求在应用的系统页增加开机后欠载次数，辅助定位阅读全屏条纹。

入口：应用 → 系统 → 更多指标。显示：

- 开机后欠载次数。
- 最近发生在开机后多少秒，所属扫描为普通刷新或物理清屏。
- 最近呈现失败/成功；成功不等于光学效果已验收。

## 统计口径

在 Metalio epdiy 的同步扫描返回点记录 `EPD_DRAW_EMPTY_LINE_QUEUE / 0x400`：普通 `lcd_do_update` 返回和物理清屏 `epd_push_pixels_lcd` 返回各覆盖一个入口。一次调用返回欠载记一次，不逐条 ISR 或逐条错误日志累计。一次用户翻页可能因初始刷新、清屏或恢复再次失败而累计多次，次数不是“受影响翻页数”。上层降频函数不计数，避免同一返回值在多个恢复分支重复统计。

`0x400` 包括队列读空、错误归属、扫描提前结束和超时，不单指容量不足。无关错误不增加计数；成功不清零。计数达到 UINT32_MAX 后饱和，不回绕；时间为单调运行时秒数，不依赖网络校时。统计保存在 RAM，重启清零；进入/退出系统、手动刷新、睡眠和唤醒均不主动清零，没有写 NVS 或清除入口。系统指标读取与同步显示扫描均由主任务拥有，不在 ISR 增加日志或持久写入。

## 其他排查方式评估

1. 本轮同时显示最近时间和清屏/刷新来源，并结合已有 PCLK、SRAM/PSRAM 最大连续块、刷新耗时，帮助用户截图反馈。全刷前后计数是否增加，比单独观察余量更有区分度。
2. 下一步可增加有界的最近故障快照：刷新模式、错误相位、首个缺失行、队列深度、当时 PCLK、恢复返回值、前台操作及后台任务类型。应在扫描结束后收集，避免 ISR 内输出拖慢供数；需同时覆盖扫描提前结束及超时，不能只看现有 `epd_feed` 单条日志。
3. 软件画布截图与屏幕照片对比可区分内容渲染错误和输出/光学异常。建议按需导出，避免常态写 SD 干扰现场；用户凭据、正文及账号数据的分享范围须受控。
4. 可选导出最近错误日志，但不建议默认持续记录全部行或上传日志。次数为 0 时不能排除驱动未检测的时序/光学问题；次数大于 0 也不能仅凭计数确认本次条纹根因。
