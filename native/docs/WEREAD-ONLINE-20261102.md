# 微读按章阅读与大书缓存

开始代码改动前的用户要求快照：`db9c837`。
版本保持 0.1.4；没有改动参考树、面板时序、电源电压或充电策略。

## 行为

- 未整本缓存的书籍点击后加载阅读位置所在章，章节就绪后自动打开。
  已有完整 EPUB 仍优先直接阅读。
- 阅读时在后台逐章预取后续三章正文，不以整本缓存/整本分页为打开条件。
- 目录、进度跳转请求未加载章时，保留当前页并优先下载目标章；取消不同目标的
  推测预取。任务结果必须对应当前书籍和等待目标；返回书架或切换书籍后不强制跳回。
- 已加载正文保留在 SD 卡，断网可继续阅读这些章节；遇到缺失章提示联网。
- 本地位置使用与原离线 EPUB 相同的书籍身份。云端进度、划线跳转可以在异步
  加载完成后继续映射位置。未完成全书分页时，显示按章节估计的进度，不编造总页数。
- “缓存图书”仍可整本下载并生成 EPUB，并复用已有章节源文件。

## 数据与调度

`native/src/weidu_stream.inc` 是独立的本地章节源，复用现有认证、正文分片、
解码和 XHTML 规范化流程。在线任务每次仅处理一章。

私有目录 `/sdcard/.thingsos/weidu/book-<id>/` 保存：

- 原目录 `toc.dat` 和可继续复用的 `chapter-<index>.raw`；
- `online-<index>-<chapterUid>.xhtml`，文件名绑定原章节 UID；
- 内部章节源描述文件 `微读-<id>.epub`，含 `TOSWRD1`、书籍元数据、规范输出
  路径及校验封印。这是阅读器内部描述文件，不是可导出的 EPUB ZIP，不进入本地书库。
  它不包含会话、Cookie 或 token。整本导出的 EPUB 仍在原 books 目录。

阅读器通过同一章节解析器读取已规范化的本地 XHTML，缺失章节不会在主任务中
同步发起网络请求。完整目录在打开时流式读取一次，不逐章扫描正文。
在线阅读跳过全书分页和全书章节导航发现；普通本地 EPUB 流程保留。

`WD_DEVICE_CHAPTER` 使用独立的一章工作单元，沿用网络唤醒/恢复策略和连接复用。
该工作单元不访问字体或显示对象，在网络、目录解析和正文整理期间释放显示/SD
全局锁，依赖完整文件原子发布供主任务读取。所有绘制、翻页、跳转和位置提交仍在主任务。

正文解码先写 `.raw.part`，通过校验后再提交；规范化内容和描述文件也经临时文件、
flush 和替换发布。失败不替换原有完整 EPUB，后台下载不触发整页阅读刷新。
刷新目录也先解析并校验临时表，成功后才替换；损坏响应不会截断当前可读目录。
规范化工作区在 PSRAM，避免消耗 16 KiB 网络任务栈；预取窗口就绪后停止扫描 SD，
只在换章或显式请求时重新检查。

## 章节数边界

移除了离线打包器人为设置的 `count > 512` 限制，ZIP 目录表改用 PSRAM 分配。
打包器仅保留 ZIP32 格式的目录项数边界（包含元数据项），没有以 512 章拒绝大书。

这不表示整个阅读器变成无限容量：现有目录/阅读数组仍有 2048 项，归档读取器
仍有 2048 ZIP 项结构限制。1548 章的《惊悚乐园》在这些结构边界内。
单章规范化和加载仍沿用约 512 KiB 的边界；本轮解决的是长篇多章节书籍的首读等待，
不宣称支持数百万字放在单一章节内的无界加载。

## 验证

主机回归新增：

- 六章书只下载指定的第四章，目录完整但其他章不被请求；已缓存章重开不发网络请求。
- 同一章节解析器可读指定章，缺失章返回未就绪；损坏分片不破坏已有章；
  损坏目录响应不破坏原目录；本地章节源和导出 EPUB 的规范身份一致。
- 模拟 1548 章完整下载、打包、重新打开并读取最后一章，覆盖旧 512 章失败点。
- 真实 draw/tap 控制器验证三章预取、跳转优先、连续改目标、缓存页手动翻转
  优先于迟到结果、断网保持位置、退出页面后不被下载结果拉回、定位请求副本的生命周期。
- Windows 控制器测试启用 UTF-8 路径；测试固件代码前先建立独立、确定的章节样本。

## 实机验收要点

新书首章、已有位置重开、前后翻章、跨远距离目录跳转、连续改目标、后台预取期间
快速翻页、关闭 WiFi 后读已加载/未加载章、退出或切书后的迟到结果、云端位置/划线
定位、旧缓存继续整本生成，以及与原固件同条件的首章时间和翻页响应。

首次打开陌生章节的阅读上下文请求仍可能需要十几至二十秒；本轮通过按需加载和预取
避免等待整本完成，没有在缺乏实测时承诺首次陌生章节秒开。
