# 音乐/录音播放控件刷新与静置显示修复

## 用户反馈与代码定位

用户反馈播放/暂停各闪两次，音乐页面未播放时静置麻点逐渐加重。

播放请求及播放/暂停点击处理先设置 app.dirty，任务异步发布新状态后 app_poll
又设置 app.dirty，可能先扫描旧状态、随后扫描已确认状态。录音试听和控制中心
存在同样的重复失效路径。音乐/录音页原先未设置 board 的 static_page，使用
普通 UI 波形和 3 秒电源轨复用窗口；微读静态页已有全幅原厂白色维护和立即
断轨/空闲校验，音频页面未接入。后者是与静置麻点相关的可疑路径，物理因果
及最终效果仍需实机确认。

## 修改

- 播放、暂停、继续由已确认的任务状态触发重绘，不先画旧状态。
- 播放的短暂 STARTING（400 ms 内）不单独触发重绘；慢启动仍只显示一次准备
  提示，任务最终成功/失败继续正常反馈。重复 STARTING 序列号不重复画同一状态。
- 录音试听和控制中心播放/暂停沿用确认后更新路径。
- 只有正在播放/录音时才由音频秒计时触发更新；暂停/空闲不靠旧秒值重绘。
- 音乐、录音、试听界面启用既有静态页面策略：平衡模式采用完整原厂 GL16
  白色维护，未变化页面跳过扫描，帧结束立即断轨并验证空闲。复用既有板级实现，
  不改电压、充电策略或扫描时序；区域计时等原有优先级保持。
