# 解锁密码关闭后重开：点击范围修复（2026-11-13）

用户补充复现顺序：关闭解锁密码后，再次点击开启，第一次无反应，紧接第二次可弹出数字键盘。版本保持 0.1.7。

## 确认的代码缺陷

`alignment.inc` 绘制的密码设置行位于左右边距 36–648、上分隔线 550 与下一行 685 之间，包括名称、开关和说明。但原 `alignment_tap()` 和 `power_pin_press()` 只接受 `470 <= x < 648, 553 <= y < 658`。点名称、行内空白或说明下缘时，开启动作不会执行；普通 tap 进入 POWER 分支末尾只设置 dirty，重画原设置页。这是由代码和旧代码失败回归共同确认的“点击后留在设置页”路径。

此前仅增加 contact 即响应，并未扩大原命中区域，故仍不能覆盖这条路径。关闭后再开启不涉及密码派生；新增的开关中心关闭/重开状态回归在修复前也通过，未证明存在 PIN_DISABLE 残留状态错误。

## 修复

- 用同一组行范围常量及 `power_pin_hit()` 覆盖整行：`36 <= x < 648, 550 < y < 685`。
- contact 激活与普通 tap 分发使用同一命中判断；保留既有手势消费，避免同一触摸松手在新键盘输入数字。
- 行边界、休眠、控制中心和确认模态保护保持有效。
- 不修改密码存储、密码验证、键盘布局、触摸芯片及屏幕电压。

## 验证与限制

## 后续只读采集

用户本轮反馈“第一次就打开了”。采集文件 `build/pin-reenable-capture-20261113-2/reenable-device.log` 实际收到数据，6 次设置页开关接触均记录同一次 `tap page=11` 后立即 `Navigate from=11 to=29`；未见对应字体/刷新错误或队列溢出。最后一次为 `x=630,y=606`，布局 72 ms、整次动作 644 ms。设备运行的是先前已安装候选，此时本轮修复仍未烧录。

该采集确认正常接触链路，未捕获“第一次失败、第二次成功”，不证明最初故障已排除。当前结论仍为：已修复确定的行命中缺口；现场偶发故障的唯一根因尚未闭环。日志采集结束后已关闭串口。
