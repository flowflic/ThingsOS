# 多章节微读缓存书优化（2026-10-31）

保持项目版本 **0.1.2**。本次落实退出/自动同步响应、分页检查点、增量目录三项。
未修改参考仓库、板级时序、面板电压或充电策略；未刷机、发布或提交。

## 退出与后台同步

- 退出先保存本地阅读记录和待同步进度，不直接启动 HTTPS。主界面完成首帧、
  输入空闲两秒后，再由主任务派发任务；关闭自动上传时不派发。电源同步沿用
  原有显式等待/取消流程，不把退出书籍等同于立即断电。
- 持久进度队列按账号隔离，最多八本书；同书以后一次操作的位置覆盖，支持
  向后翻。每次写入带代次，旧请求完成不能清除新位置。队列满/损坏时返回
  保存失败，原记录不被静默淘汰；本地阅读位置仍由阅读记录系统保存。
- 时长和阅读会话只在内存中保存一次任务快照；成功派发即消耗，不把时长写进
  重试队列。失败后仅重试进度，避免响应丢失后重复计时。重启不补报旧时长。
- 每本书的退出任务持有独立会话快照，后台退出上传不会改写新书的活动会话。
  空队列每五秒探测一次，失败请求一分钟后才尝试持久进度，避免空闲循环读 SD。
- 新增组合式 HTTPS transport：仍在原显示/SD 互斥保护下推进 TLS，底层等待
  每次 1 ms；连续读写在 10 ms 片段后以 EAGAIN 交还 SDK 状态机。请求仍有
  独立的 60 秒总预算，POST 不在推进循环内重新发送。

### ESP-IDF 适配与来源

本机 IDF v6.1 的 `esp_tls.c` 在异步 CONNECTING 中重复使用 `select()` 会修改的
fd_sets。短轮询超时后，集合已为空，必须在下一次检查前重建。
`native/reader_tls_poll.cmake` 将已安装 SDK 文件复制到 **build/**，仅在这处
select 前重建读/写集合，以该副本替换本次主应用的编译输入。Apache-2.0 与
Espressif SPDX 头保持完整；安装目录和参考仓库不变。源码匹配失败时构建停止。
来源也已记录到 `upstream-sources.json`。

自定义 transport 的内部 TLS 错误仍从官方底层 transport 读取，保留 CA 验证、
域名验证、现有 Web 根证书和个人划线专用证书 bundle 边界。

## 按章保存分页

- 只保存已经完成的章节，包含章数、已完成章数、版式/字体/内容键和校验。
- 章节完成且距离上次检查点至少五秒时保存；退出和重建版式前补存已完成部分。
  当前未完成章从章首重算，不持久化借用字体/章节指针的排版游标。
- 独立 `.partial` 文件和 magic，完整索引加载器不会把半成品当全书。
  重开可从下一完整章继续；完整分页成功保存后清理检查点。
- 保持原章节/原文位置作为书签与云端定位依据，不把易变页码作为持久坐标。
- 本轮没有增加多套字号缓存，也没有预渲染全书。

## 增量目录

- 进入目录不再同步调用全书标题/子目录扫描；先绘制已有根目录。
- 标题补全每步至多一章；微读子目录初始化只读暖缓存或发布全部根节点，
  后续每步至多读一章原文并补入经过原文映射验证的子目录。
- 返回阅读即停止目录后台步骤，重新进入可接着处理；成功后保留原有
  `navigation.cache`，损坏或 EPUB 内容变化时重建。
- 插入子目录时保留视口顶部的原章节/位置。点击使用上一次真正绘制的行目标，
  避免新索引已插入但墨水屏尚未更新时跳错章节。变化合并后最多约每秒重绘。
- 书籍 spine 不重排，书签、批注与云端源章节编号不变。

## 验证与边界

- 主机回归 **45/45**：增加网络 1 ms 等待和持续流让步测试、部分分页键/CRC/
  结构损坏与完整索引隔离测试；扩展真实 UI 的延迟派发、分页恢复、目录首帧
  和绘制行点击目标测试；扩展多书/账号/代次/容量/损坏备份的进度队列测试。
- 主/救援构建结果及候选哈希记录在 `build/large-reader-verification.json`；
  日志为 `build/large-reader-host.log`、`large-reader-main.log`、
  `large-reader-rescue.log`。
- 单步短等待不等于所有处理都严格 10 ms：TLS 密码运算、单章解压/解析、
  原文映射、SD 写入仍是有界但同步的操作。主机测试不能代替这些实机尾延迟。
- 尚需 Metalio 实机复测《明朝那些事儿》冷/热开书、反复退出/切书、慢连接、
  断网恢复、目录滚动/跳转、分页中途重开和显示欠载。此前“单次网络引入的
  等锁 <100 ms、退出约一秒可操作”仍是实机验收目标，未宣称已达成。
- 若退出时尚无可用源位置映射，现有 `wd_position()` 仍会尝试当前章的映射。
  本轮消除了网络长等待和整书目录入口扫描，未把所有单章 CPU/SD 工作改为
  可抢占任务；需要用后续实机分段日志决定是否继续切分。

候选保持未安装状态。刷机需针对该候选另行授权，并遵循
`METALIO-USB-FLASH-PROCEDURE.md` 的备份、救援、回读及启动健康流程。
