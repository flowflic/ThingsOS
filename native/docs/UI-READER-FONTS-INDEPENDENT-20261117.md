# 系统界面与阅读字体独立

用户要求“系统界面字体和阅读字体分开设置，不保持同步”。检查原实现：字号、字重各有 `ui-px`/`px`、`ui-weight`/`weight`；字体文件则只有 `app.font` 和 NVS `font`，两处字体选择共用同一对象。

现在系统界面和阅读正文分别拥有 FreeType 对象及字形/文件缓存，NVS 分别保存 `ui-font` 和原来的 `font`。设置第一项明确为“界面字体”，正文菜单仍为“阅读字体”；各自预览当前字体，并按各自字号、字重显示预览。修改界面字体不会替换阅读字体、改变正文字号或失效正文分页；修改阅读字体只重建阅读分页/缓存。界面字号上限仍为 50，两个字号和字重保存项继续独立。

旧 NVS `font` 保留为阅读字体。没有 `ui-font` 的设备使用内置界面字体，之后不会根据阅读字体自动同步。UI 标签、导航、输入框、控制中心、蓝牙等界面使用界面字体；正文、脚注和批注正文继续使用阅读字体。读取字体失败时分别回退，界面字体恢复不重置阅读字体。移除 SD 卡和 USB 原始磁盘模式同时释放两套字体的 SD 句柄，避免遗留第二个文件句柄阻止卸载。

回归覆盖两处字体应用的对象/保存项隔离、界面字体不改变正文分页及字号、阅读字体不改变界面对象/字号、两套字体各自的故障恢复。候选编译、主机测试及安装证据与统一蓝牙入口共存于 `build/bt-unified-20261117/`，版本保持 0.2.0。主机画布及启动健康不能替代设备上的自定义 SD 字体验收。
