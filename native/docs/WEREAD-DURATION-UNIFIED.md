# 阅读时长统一开关与当日已上传统计

2026-11-14 用户要求：同步页直接显示开关状态，合并在线时长与离线补传开关；“阅读时长”改为当天已成功上传的累计。用户确认跨日补传按阅读发生日期归档，昨天离线、今天上传仍归昨天。版本保持 0.1.7。

## 交互

同步页只保留“上传阅读时长（含离线）：开 / 待确认 / 关”一个控制项，同时控制时长采集、在线上报及离线队列自动补传。“阅读时长明细”只读显示同一状态，保留待上传、待确认、原补传通道累计、今日已上传和必要的授权、位置冲突处理入口，没有第二个开关。

阅读时长首次同意仍保留。授权仅改变补传通道可用性，成功、失败或取消均不改动总开关；已有同账号授权继续复用。关闭不会删除队列，关闭期间的阅读秒数不会因为后来开启而回报。每本书仍固定一种计时归属，不让 Web 和 Native 两条通道重复上报同一段；改通道后重新开书生效。

以原 `wd-time` 作为唯一设置来源：合法的已保存关闭状态保留；缺失/无效值默认开启。旧 `wd-offline` 不再独立读取，保存时仅作为同值兼容副本。用户拒绝或接受首次同意、保存失败回滚、重启读取均同步两个内部控制位。

## 当日累计

同步页显示当前账号在本机留存的明确成功记录合计：Web 在线上报成功秒数 + Native 时长批次成功秒数。未发送、失败、未知回执均不增加成功累计。Native 队列联网期间上传的成功记录也在合计内；通道分类不等同于阅读时是否有网络。

- Native 批次按记录内原始历史小时及其时区分配阅读日期，补传旧日期不会抬高今天。
- Web 使用实际发送的有效时长及发送前采样的阅读区间结束时间，跨北京时间午夜拆分；不按回执到达日期计数。
- 页面日期使用北京时间，与当前阅读采集的 UTC+8 一致；跨午夜重新加载对应日期。
- 每账号持久化最近 32 个阅读日期。旧历史批次不能挤掉较新的当天记录；Native 原有终身累计继续保存。
- 这是本设备记录，不冒充账号所有设备的全量统计。旧版本只有无日期的 Native 总累计，不能可靠回填为某日；升级保留旧总量，当日分项从有日期的成功记录开始建立。

## 持久化与边界

`eink_readtime_totals.inc` 在原账号绑定 NVS 命名空间中使用 `total-v2` 单个 CRC 校验 blob，将 Native 终身累计、两条通道各自最近回执指纹及每日分项一并提交、回读核对。缺少 v2 时可只读迁移原 `total-v1`；损坏或账号前缀碰撞校验失败会停止记账，不把错误当成零。

Native 必须先有明确 `succ` 回执，且本地成功统计落盘后才确认删除源记录；失败保留原 `.sent` 保护，绝不为修复统计自动重发网络请求。Web 同样只在明确成功后记账；本地统计保存失败会报告存储错误，不重放已接受的 POST。断电发生在远端接受到本地成功记录提交之间，仍可能只留下不确定结果；显示统计不是云端账本的替代品。
