# Metalio 0.2.1 正式版构建

2026-11-21 用户要求把项目版本升级到 0.2.1，编译正式版固件，去掉部分调试信息，保留诊断日志功能。
正式包完成构建后，用户授权分步安装主程序与救援环境，并确认了官网更新说明。官网说明见 `native/release-notes.json`。

## 自 0.2.0 起的主要变更

- **屏幕扫描稳定性**：Cubox 下载图片、微读联网加载、音乐开始播放时偶发"欠载刷新"的根因已查清。原因是 CPU0 上 LCD DMA 完成中断偶尔晚到 100 µs 以上，超过双缓冲的余量。为此改了三处：
  - S31 改为 3 个 bounce buffer，迟到的完成中断会按顺序补齐，同时保留描述符身份校验；
  - LCD GDMA 中断提到 level 3，注册为 IRAM 安全；
  - 行队列改为整块连续分配，指针数组放回内部 RAM。

  实测中断间隔达到 290–294 µs 时已由补齐兜住，没有欠载。真正欠载时的兜底时钟由 10 MHz 改为 16 MHz，之后自动回到 20 MHz。
- **诊断日志格式 2**：
  - 512 条近期事件，另有独立的 64 条失败事件环，网络事件再多也挤不掉失败记录。
  - 整份记录放在 PSRAM，由互斥锁保护，不占内部/DMA SRAM。
  - 屏幕扫描失败时额外记录原因（kind 11 stage 5/6），字段说明见 `DIAGNOSTICS-20261115.md`。
- **控制中心**：新增蓝牙、振动开关，样式与 Wi-Fi、前光一致。蓝牙长按或点箭头进入蓝牙页并开始搜索，返回后回到控制中心；振动开关与"按键振动"设置同步。
- **蓝牙与内存**：
  - 低功耗控制器的启动预算恢复到门槛以上（开机 DMA 空闲约 70.8 KB），翻页器可以正常连接；
  - NimBLE 缓冲池按单连接缩减；
  - `esp_cache_msync` C2M 改为每 4 KiB 分块，缩短关中断时间。
- **Cubox**：暂停的音乐若是唯一占用网络的会话，Cubox 刷新/下载前会先停下它并记住播放位置，再按播放可从原位置继续，不再提示"请等待当前传输任务结束"。
- 0.2.0 之后已安装验证过的其他修复见以下记录：
  - 音频：`AUDIO-DMA-START-20261117.md`、S31 LP RAM 音频卡顿修复；
  - 蓝牙：`BLE-*`、`BLUETOOTH-UNIFIED-UI-20261117.md`、`WIFI-BLE-DMA-20261118.md`；
  - 微读：`WEREAD-*`；
  - 阅读与界面：`READER-CONTROLS-TOC-20261118.md`、`UI-*`。

## 正式版去掉的调试输出

只去掉排查期间加入的高频输出和测量钩子：

- 每次刷新的 `epd_feed refresh core…` 供数统计（失败相位统计保留）。
- 每次刷新的 `CKV final phase pulses`（出错时仍输出）。
- `epd_irq` 近似欠载日志与开机行队列地址（欠载时仍输出一行原因）。
- `esp_cache_msync` 计时包装（`-Wl,--wrap`），已证明与欠载无关。
- 音频每 5 秒的播放统计与全任务 CPU 遍历；只有真的发生 I2S 欠载时才输出。
- 蓝牙模块串口收发明细降为 DEBUG（其中含设备名），默认不输出。

诊断记录、失败原因事件、中断间隔/补齐统计、错误与告警日志全部保留。

## 验证边界

- 主机 CTest 71/71 通过。
- 0.2.1 的功能内容来自 2026-11-20 晚间已在实机安装验证的候选 `cc-diag2-20261120`（ELF `25ac06c9d…`）。该候选通过了救援实际启动、16 MiB 回读、保护区/NVS 一致和 45 秒启动健康检查。
- 0.2.1 相对该候选只做了版本号和调试输出的改动。正式版主程序和救援环境分别完成实机安装与回读，救援 HTTP 就绪，主程序通过 45 秒启动健康检查。记录见 `build/release-0.2.1/usb-install/` 与 `build/release-0.2.1/rescue-install/`。
- 控制中心新开关、诊断格式 2 导出、欠载原因记录仍待用户操作验收。
- 急救 0.1.8 读不懂诊断格式 2（按大小/CRC 拒绝，不会误读）；安装 0.2.1 完整 USB 包后救援环境也会是 0.2.1。
