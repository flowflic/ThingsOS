## 临时上传凭证

旧代码只接受 JSON number 形式的 `start_time/expired_time`。现同时兼容严格的
十进制字符串形式；数字必须是整数，拒绝尾随字符、符号、溢出、非法日期范围
及到期不晚于起始的值。IMA 文档将其定义为 int64，此前未捕获用户真实临时
凭证的字段类型，因此不能把这一兼容点直接宣称为现场上传失败的唯一根因。

原错误把字段格式、堆分配、哈希/签名失败混为一条。现分别提示媒体标识、
存储桶/区域、对象路径、密钥/令牌、有效期、工作区内存或签名错误；不显示
任何实际凭证值。约 5 KiB 上传工作区与签名临时缓冲优先使用 PSRAM，减少
内部 SRAM 碎片影响。

测试执行真实上传流程，覆盖数字、字符串及混合时间字段的成功路径，以及
小数、尾随字符、溢出、逆序有效期、缺失令牌的拒绝路径。普通签名向量、
重名、不确定结果核对和取消仍保留。

## 微读准备文字残留

准备阶段与读取目录阶段都使用 WD_DOWNLOAD，原 UI 将同阶段首次文本变化
当作 DU 进度更新。旧抗锯齿文字可能未充分清除。现在只在离开
「正在准备微读服务」的首次阶段变化时使用正常灰阶 UI 刷新；后续章节
进度仍使用原有受限频率的局刷。没有改变板级波形、电压或时钟。

UI 回归覆盖同 phase 准备→目录时不走进度 DU，以及后续普通进度仍走局刷。
墨水屏实际清理效果仍需安装后现场验证。

| 2 | 27 ms | 79 ms | 191 ms |

用户确认系统相机/浏览器扫码慢，而直接输入同一 HTTP 地址很快。

尚未区分二维码识别、扫码跳转或手机端检查等具体环节，不归因于某项
未经验证的浏览器机制。网页为静态内联页面，打开时不调用 ima 云端。
