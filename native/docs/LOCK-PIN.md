# 六位数字解锁密码

2026-11-12，用户确认 `build/prototypes/lock-pin-20261112/` 原型后实现。

## 使用方式

- 设置 → 电源与锁屏 → 解锁密码，默认关闭。开启需输入两次相同的 6 位数字。
- 修改密码先验证当前密码，再输入并确认新密码；关闭也需验证当前密码。
- 数字键使用原型的 188 × 112 像素触摸区域。输入显示圆点，最多六位，支持删除、取消和明确提交。
- 密码错误清空本次输入，保留密码页；两次新密码不一致只清空确认输入。
- 唤醒与冷启动先显示密码页，验证通过进入书库首页，不自动打开锁屏前的书籍。
- 解锁页没有首页导航或返回入口；“取消”和返回/菜单键重新息屏，首页键不能跳过验证。
- 关闭密码后保留原来的唤醒目标和锁屏行为。重启、关机和壁纸入口继续保留。

## 实现边界

`firmware/main/lock_pin.h`、`lock_pin.inc` 是主任务拥有的状态、校验和数字键盘。新页枚举附加在 `THINGSOS_UI_LOCK_PIN`，不改变既有页枚举值。普通 UI 设置快照不包含密码，避免其他设置的保存覆盖密码状态。

`thingsos-ui/lock-pin-v1` 是一个整体 NVS blob，包含格式、启用标志、16 字节随机盐和 32 字节 PBKDF2-HMAC-SHA256 校验值（10000 轮）。设备使用 ESP-IDF 的 PSA 实现，主机使用 Windows CNG 并对照独立已知值。没有明文密码 NVS 项，也不把密码写入 SD 卡。只有 blob 写入和提交成功后才替换运行时校验记录；保存失败保留原启用状态。输入与编辑缓存在离页、取消、休眠、成功后擦除。

缺少命名空间或密码键时按未启用处理，兼容旧固件。已存在的无效/截断密码记录和 NVS 读取故障保留锁定，显示明确故障提示，不能静默退回无密码首页。无忘记密码的跳过按钮；丢失密码或损坏记录需要受控的恢复维护。此功能控制主应用屏幕访问，不是 SD 卡加密或网络服务认证，也不改变救援固件的恢复职责。

`navigate()`、绘制、触摸、实体首页/菜单键、控制中心下拉、AI 录音键和音量键共同检查锁定状态。SD 拔出或后台重新导航不能让受保护内容成为可交互页面。闹钟可停止/稍后提醒，关闭提醒不解除密码状态。USB 返回标记也不能绕过冷启动验证。

解锁前仍使用原有锁屏壁纸/统计。唤醒到密码页与密码验证成功到首页保留既有反向水波纹全刷；普通数字输入不触发锁屏过渡动画。没有改面板电压、时序、VCOM、充电策略或分区。

底层 `thingsos_board_private_input()` 用原子标志通知触摸采样任务停止坐标日志。`thingsos_touch_privacy_t` 将保密状态保留到该次接触松手，避免页面切换后记录末次触摸坐标；UI 层的触摸日志和可选 bring-up 跟踪同样排除密码页。

- 覆盖冷启动、真实共享息屏/唤醒函数、强制导航、首页/返回键、控制中心、AI 键阻挡，及密码 blob 截断/异常、NVS 不可用的闭锁行为。
