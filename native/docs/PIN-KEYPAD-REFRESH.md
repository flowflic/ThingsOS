# 解锁数字键盘采用局部输入快刷（2026-11-13）

用户反馈：输入解锁密码时，每输入一位数字整页闪烁一次，希望与 Wi-Fi 密码键盘相同。

## 原因

PIN 输入和删除原来仅设置 `app.dirty`。主渲染分支只给 `THINGSOS_UI_PASSWORD` 的 QWERTY 输入选择局部键盘刷新，PIN 页进入普通整页 UI GC16 路径。只读日志 `build/pin-reenable-capture-20261113-2/reenable-device.log` 同样记录多次 `page=29` 输入后的 GC16 整页更新，扫描约 528–530 ms。该问题与此前尚未闭环的首触偶发失效分开。

## 修改

- 普通数字、删除和验证错误设置输入刷新标志。数字未改变且无提示需清除时，不请求多余刷新。
- PIN 页复用 Wi-Fi 的 `keyboard_present()`、快速 DU 波形与同一双区域扫描函数，整次输入只扫描一次。只替换 PIN 区域：逻辑行 `[320,478)`（标题、圆点、提示）与 `[1090,1166)`（提交按钮）。
- 打包和扫描使用相同区域定义；数字按键、锁图标、页头、两区域之间的空白均保持，不逐键重画整页。
- 第六位输入后按钮变为实心，删除后恢复空心；采用黑白边框以适配 DU 的黑白输出。
- 进入/退出密码页、设置/验证阶段改变、锁屏水波纹、强制清屏及故障恢复仍走完整刷新。渲染开始前固定本帧是否局部刷新，避免清除过渡标志后误选局部输出。
- PIN 输入属于现有 editor frame；延后周期清屏并在更新后沿用 Wi-Fi 键盘的立即断电及 idle verify。没有改硬件时序、VCOM、充电安全策略或密码存储。

## 验证

- 新增输入刷新回归在旧代码下失败：`app.input_refresh` 未设置，证据 `build/pin-keypad-refresh-20261113/before-test.log`。
- 实际主控制器测试覆盖逐位输入、六位上限、删除、错误提示、阶段切换、强制刷新与锁屏过渡保护。逐像素检查局部绘制没有改动上述区域之外的画面，且与相同状态下的完整绘制一致。
- 实际 `keyboard_present.inc` 与 EPD 双区域实现测试覆盖 PIN 单次 DU、区域边缘/向量填充不泄漏、失败不提交 back buffer、原 Wi-Fi DU 输入和 GL16 布局刷新；既有暗色分支保持原行为。
- 控制器和区域扫描测试通过，主固件构建及 JPEG 链接检查见本机 `build/pin-keypad-refresh-20261113/`。

版本保持 0.1.7。本轮没有烧录或发布；编译与主机像素/扫描检查不代替面板视觉验收。
设备后续已安装包含本修复的最新版 0.1.7，用户确认输入快刷正常；日志与安装记录见 [DEVICE-INSTALL-20261113-PIN-REFRESH.md](DEVICE-INSTALL-20261113-PIN-REFRESH.md)。
