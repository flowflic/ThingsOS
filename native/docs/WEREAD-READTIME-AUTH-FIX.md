# 离线时长授权准备后退出修复与登录复用边界（2026-11-13）

## 现场与根因

用户报告进入“离线阅读时长 → 微信扫码授权时长通道”后，仅显示准备提示就返回原页。只读采集已收到并由用户确认复现：`action=20 / WD_DEVICE_RT_AUTH`，约 1709 ms 以 `error=1 / WD_NETWORK` 结束。原固件未记录单次 HTTP 响应大小。

本轮只读探测公开、匿名的授权接口，未使用用户凭据，也未扫码、交换账号令牌或提交阅读时长。`wxticket` 为 HTTP 200、97 字节；SDK `qrconnect` 为 HTTP 200、68650 字节，除了 uuid 还包含二维码图片对象。普通/带 last=0 的匿名首次轮询均等待至探测超时，未发现会立即拒绝的差异。

实际设备传输代码将所有响应统一限制为 16384 字节，SDK 图片响应会在获取 uuid 前触发 overflow；旧代码将该 HTTP 200 超限结果仍返回 WD_NETWORK。使用约 70 KiB 图片字段的完整 JSON 执行真实传输函数，旧代码稳定失败，与现场错误分类一致。另一个独立问题是设置页优先显示“未授权，请扫码”，掩盖已有错误，所以用户看不到退出原因。

只读现场日志及非敏感响应统计：本机 `build/readtime-auth-fix-20261113/device-before/`。串口已关闭。没有把匿名探测的 68650 字节表述为旧设备日志实际记录到的响应大小。

## 修复

- 仅 SDK 二维码 GET 的响应空间提高到 128 KiB，使用 PSRAM 且保留总长度上限；其他接口仍是 16 KiB，不整体放宽上传/配置响应预算。
- 解析 uuid 后，沿用原代码释放服务端图片 JSON，并在设备本地生成确认二维码；不持有额外图片或改变显示/存储格式。
- 响应超限明确返回 WD_LIMIT；失败诊断只记录 HTTP 状态、字节数、预算及结果，不记录 URL 查询、二维码 ID、正文或任何凭据。
- 首次授权失败的错误提示位于“未授权，请扫码”的通用提示之前；队列损坏/满等专用保护提示继续保留。凭据内存分配失败也会发布错误状态。
- 准备提示改为“正在获取时长授权二维码”，二维码阶段明确显示“微信扫码授权时长”。
- 待发队列认领、结果未知不自动重传、同账号绑定和现有凭据保存/续期逻辑保持。

## 关于复用微读登录

当前 Web 微读会话为 vid/skey/rt，Native 时长会话为 vid/accessToken/refreshToken/deviceId。不能仅复制登录状态或将 Web skey 当作 Native accessToken。

已核对固定版本原始实现：

- [weread-omni QR 登录](https://github.com/teng-lin/weread-omni/blob/88bd2e095d7d7ee423eaadf8f40653e72c5be6d4/src/auth/qrlogin.ts)：单独请求 Native QR，确认后经 `/login` 获取 Native 凭据。
- [觅阅 shelf_client](https://github.com/miumiupy98-art/miuread-koreader/blob/418380a0638381fcd8e2bad8d1f23be79fddd7c4/miuread.koplugin/miuread/shelf_client.lua)：Native 凭据单独保存为 native_shelf，与 Web 账号比对后合并到账号存储；它也采用额外客户端授权，而非将 Web Cookie 直接用于 Native。

在本次核对范围内，没有确认可直接复用现有 Web 会话而免去首次 Native 授权的兑换流程。现有 ThingsOS 已将 Native 凭据保存在 NVS，按当前 vid 校验，并在 Native GET 遇到授权失效时使用 refreshToken 续期。因此一次成功授权后可持续复用，不需要每次启用功能或重新打开书籍都再扫码。首次也统一为一次扫码涉及登录协议/后端统一，不能靠合并两个布尔登录状态完成，本次没有迁移整个微读后端。

## 验证与交付范围

- 旧代码的大 SDK 响应传输回归和未授权错误可见性回归均失败；修复后通过。
- 覆盖大于旧上限的 QR JSON、其他接口仍受 16 KiB 限制、超出 128 KiB 的 QR 响应拒绝；每次请求的连接资源均释放。
- 原有 POST 首字节前落盘、连接失败保持 pending、可能发送但结果未知不自动重试，以及不跟随重定向等传输检查继续通过。
- 真实 UI 控制器验证错误提示、前台二维码不被时长设置页遮住、有效已保存授权的开关操作不发起新的扫码，以及原有独占计时/时钟回拨边界。
- 版本保持 0.1.7。主固件构建及 JPEG 链接检查、镜像指纹见 `build/readtime-auth-fix-20261113/validation.json`。

修复完成时尚未烧录；后续已随单开关候选按用户要求完成 USB 安装、完整回读及启动健康检查，见 [安装记录](DEVICE-INSTALL-20261113-READTIME-SINGLE-TOGGLE.md)。未发布；实际扫码确认、令牌续期及账号时长入账不由主机测试或启动健康代替。候选包含章节目录当前项高亮与自动定位修改。
另外修正了冷启动状态恢复：设置页读取时长状态时，若客户端已初始化、worker 空闲且尚未加载时长状态，则先从 NVS 恢复并按当前 vid 验证已保存的 Native 凭据。避免尚未启用补传时把已授权误显示为未授权。worker 活跃时仍只读取快照，不并发读取账本；可能触发状态恢复的当前调用位于 UI 主任务持有 I/O 锁的路径；worker 活跃时只读取快照。此分支已构建验证，已有授权跨重启的完整实机扫码验收仍未进行。
