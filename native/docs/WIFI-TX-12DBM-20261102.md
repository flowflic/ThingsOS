# Wi-Fi 请求 12 dBm 上限（2026-11-02）

按用户明确要求，在当前 Metalio 工程应用名义 **12 dBm** 的运行时最大发射功率请求。版本保持 **0.1.4**，保留已完成的 b/g/n 与微读联网省电策略修改。

后续实机：包含此限制的充电修复候选已按授权安装，STA 启动及微读任务均回读 48 quarter-dBm；原救援保持不变。见 [2026-11-02 实机测试](CHARGING-WIFI-DEVICE-20261102.md)。下文「未安装」描述保留为原实现阶段记录。

## 实现

`native/firmware/components/thingsos_net/wifi_tx_power.inc` 是唯一的请求值定义：

```c
#define WIFI_TX_POWER_LIMIT_QDBM 48
esp_wifi_set_max_tx_power(WIFI_TX_POWER_LIMIT_QDBM);
```

API 单位为 0.25 dBm，所以 48 表示请求 12 dBm。调用后通过 `esp_wifi_get_max_tx_power()` 回读，接受不超过 48 的合法档位，包括本 SDK 文档所列的 44（约 11 dBm）。请求失败、回读失败或回读超出上限时返回错误；调用方停止该次射频启动，不继续使用未确认的功率设置。

日志格式：

```text
WiFi TX limit request_qdbm=48 actual_qdbm=<驱动回读值>
```

`actual_qdbm / 4` 是驱动报告的功率档位，不是仪表实测的每包输出。

`network.c` 有两处入口共用该实现：

- `wifi_radio_start()` 在驱动启动成功后同步设置并回读，调用者返回后才继续连接/扫描/服务流程。
- `WIFI_EVENT_STA_START` 和 `WIFI_EVENT_AP_START` 在 STA 自动连接逻辑之前再次应用，覆盖板层直接启动射频的唤醒路径，以及射频已运行时新增热点的路径。

主固件与救援共用此网络组件，因此普通 STA、传输热点和救援 AP 都请求同一上限；请求作用于共用射频，不是为每个接口分别增加功率。接口事件重复应用是幂等的。

保留 `CONFIG_ESP_PHY_MAX_WIFI_TX_POWER=20`，运行时限制与官方方法一致；本轮不调整 PHY 初始化数据、国家/信道、协议掩码、TCP 参数或省电策略。API 要求 Wi-Fi 启动后调用，不能把该运行时请求表述成启动前 PHY 校准阶段的功率测量。
