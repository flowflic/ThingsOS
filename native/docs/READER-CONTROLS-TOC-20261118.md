# 阅读菜单边缘点击、目录二次跳动与系统页简化

## 阅读设置：字体 / 更多需要多次点击

不复位设备的实机采集位于 `build/reader-controls-toc-20261118/live.log`。用户确认复现后，日志记录两次有效屏内触摸：1387968 ms `(104,1205)`、1389514 ms `(103,1210)`，均进入阅读页的 tap 分发，但没有进入字体页；此前 `(110,1186)` 正常进入字体页。说明这些点击并非触摸采样丢失。

原竖屏底排按钮的热区为 Y=1132..1199，留下 16 像素的底部空白；两次复现坐标均落在该空白。未命中动作仍会执行保存/重绘，产生“点了但不进入、菜单又刷新”的体验。随后 `(517,1175)` 成功进入更多页，支持同一底排热区机制；并未捕获到更多按钮自身的一次失败，不能把所有偶发未响应都认定为同一原因。

修复：底排按钮的纵向热区覆盖到可见屏幕底边（竖屏 1215、横屏 683），横向按钮间隔保持无动作，不跨入盖板虚拟按键区域。菜单动作 NONE 提前返回，不保存设置、不请求无效重绘。回归使用实测坐标，并覆盖本地/微读、横竖屏、左右间隔及屏外拒绝。

## 阅读设置 → 目录：进入后不到一秒跳动

用户明确所指是章节列表。本次实机采集没有该页进入记录，因此以下定位来自源代码路径和生产控制器回归，不能声称已捕获该次物理闪动。

目录先显示已有标题，再由 `reader_toc_poll()` 增量补全标题和小节并重新居中；当新小节插入可见顶部与当前章之间，会改变顶部目录项。主循环还允许在目录页继续分页，分页完成/失败时请求该页后台重绘。在线预取完成则直接释放小节目录并将目录页置脏。这三条代码路径均可能在首屏后引入一次更新；本轮未用现场目录日志区分具体由哪条触发。

最终方案遵从用户补充要求“当前章节目录还是要居中”：保留进入目录时的当前章/小节居中逻辑，不改成固定顶部锚点。目录可见时暂停标题/小节补全和后台分页；在线预取完成仅标记小节目录待失效，不释放正在使用的数据、不将目录页置脏。因此无需为这些任务再扫描一次目录页面。

标题补全改在纯阅读页空闲 1.5 秒后逐章进行，菜单、图片和批注等浮层阻止该任务；相邻页预绘优先。离开目录返回阅读后继续补全，并应用待失效的小节目录。若快速打开目录而补全尚未完成，先使用现有标题/页码，退出后继续准备，下次进入再显示更新后的数据，不在已显示列表上自动重排。必要的显式刷新、故障恢复和真实状态变化不在此次取消范围内。

回归覆盖居中进入和重新进入、目录可见时补全/失效标志不消费且不置脏、手动翻组后仍保持视图、纯阅读空闲时继续准备且不要求画面刷新、菜单阻止准备，以及已绘制行的点击目标不被后台替换。
