# Metalio 阅读白底黑色散点累积修复（历史候选）

后续实机反馈：每页黑闪明显，且静置同页仍出现黑点，原先的根因判断未获验证。完整白底复位已撤回，当前调查见 [静置黑点与低闪候选](READER-STATIC-SPECKLE.md)。

日期：2026-10-25。版本保持 0.3.6。用户反馈：阅读翻几页后整页白底出现黑色散点；手动全刷可恢复干净。照片显示的是物理面板，不能用主机截图代替验收。

## 定位依据

- 当前读配置日志为均衡 `mode=0`、关闭动画 `ripple=0`、15 次全刷，面板时钟 20 MHz。普通阅读进入 `text_waveform`，以全像素发送；这不是没有扫描白底，而是给白底发送了过弱的动作序列。
- 原 `thingsos_refresh_text_wave()` 先屏蔽全部相同灰度的动作，再只恢复最后一个白色脉冲。真实 36 相表的 `15→15` 从 **11 相黑 + 17 相白** 变成 **0 相黑 + 1 相白**；相数仍为 36，启动时打印相数无法揭示这一区别。
- RAM 中的旧白色值不代表物理纸面已经干净。原路径允许白底长期跳过复位，和“逐页累积、全刷消失”的表现一致。用户确认及序列检查支持这一原因；主机检查本身不能证明修复后的光学结果。
- 新回归断言先在旧实现上失败：`source black/white=11/17, reader=0/1`。原测试把“白底只有一个脉冲”当成正确预期，因此无法检出该缺陷。

## 修改

新增 Metalio 板级 `thingsos_panel_text_wave()`，在保持其他相同灰度像素的同时，逐相完整保留所选源表的 `15→15` 序列，包括两个极性和保持相。不猜测新的脉冲数，不修改只读参考表。

普通均衡阅读和水波纹翻页两条路径都使用该函数。两条路径原有的全像素/全行列发送继续保留，避免差分掩码再把白底复位跳过。

保持原有 36 相普通翻页、48 相周期清理、20 MHz 时钟、NVS 全刷间隔、VCOM、供电、充电安全和 Metalio 外设。快速 DU 模式仍保留速度/残影权衡；本次针对用户当前的均衡阅读路径。

**可见代价：** 原先未变化的白底也执行完整黑白复位，所以均衡阅读翻页的白底闪动会更明显。扫描相数没有增加，但不以此声称设备端耗时完全相同。只增加一两个白脉冲虽能少闪，却没有当前面板的验证依据，故本次采用所选源表已有的复位过程。

## 面板验收

同一本书、字体/字号、均衡模式、温度及全刷间隔不变，清理一次后连续翻 20–30 页；分别检查周期全刷前的白边、行间、旧字位置和页脚是否累积黑点，同时记录闪动感、翻页速度和欠载日志。再检查横屏和水波纹路径。光学验收以用户目标设备观察为准。
