ThingsOS for Metalio E-Ink4-Plus

This plan ports ThingsOS 0.3.5, the reading-first e-ink OS built for the Read Pico, to the Metalio E-Ink4-Plus. Both devices use the same 684 × 1216 screen, so the whole UI carries over. The work is mostly hardware: a new chip, a new panel power path and a new set of peripherals.

§1

Why this port is feasible

ThingsOS already keeps the hardware behind one interface, thingsos_board/board.h, which has about 35 functions for drawing, touch, tilt, time, battery, sleep and USB. The app layer (native/src, about 9.4k lines, plus firmware/main, about 7.6k) doesn't depend on the board, and its 23 host tests run without hardware. The panels match pixel for pixel, so prototype v3, landscape mode and every touch area are reused as they are.

The interface has a few leaks to fix first. There are 23 direct calls to read_pico_*, cst836u_* or pmu_* spread across main.c, network.c, weidu_device.c and the rescue app. board.h exposes the CST836U touch type. The USB and cache headers are hard-wired to the ESP32-S3.

§3

Goals and non-goals

  • Goal: ThingsOS 1.0 runs on Metalio and matches every reading feature of 0.3.5.
  • Goal: Users can use the hardware only Metalio has: frontlight, volume keys, haptics, the RTC and a real power-off.
  • Goal: One codebase builds for both boards. Board choice is a build setting, and shared code has no per-board forks.
  • Goal: The safety model of 0.3.5 stays intact: rescue partition, boot guard, verified OTA and factory-owned VCOM.
  • Non-goal for 1.0: LVGL, the xiaozhi voice stack, the Metalio cloud push service (its endpoints are blank in the open-source repo) and Bluetooth audio.
§4

Users and scenarios

  • Long-form reader: reads EPUB, TXT and Markdown from SD for hours. Wants fast page turns, little ghosting and reading statistics they can trust.
  • WeRead (微读) user: syncs their shelf, highlights and notes, and reads cached books offline.
  • Night reader: uses the warm frontlight in bed and turns pages with the volume keys without touching the screen.
  • Collector: loads books and fonts over Wi-Fi, the hotspot or the USB disk mode.
  • Tinkerer: updates firmware from the browser and expects to recover from a bad build without opening the case.

§6

Functional requirements

Display

FR-DSP

Bring up the panel with the TPS65185 power sequence and the ED047TC2 waveforms. Support full GC16, partial differential refresh, the staggered page turn, keyboard and status-bar row updates, and a clear-then-redraw before sleep.

Accepted when: ghosting after 20 page turns matches the Read Pico or is better; a full refresh happens every N pages as configured; no frame tearing while Wi-Fi is active; panel temperature is read and checked before every drive.

Touch and keys

FR-INP

FT6336U with the existing tap, drag and long-press logic. Bezel keys come in as touch points at Y ≈ 1600. Vol+ and Vol− turn pages in the reader. POWER short press locks or wakes, long press powers off. Landscape rotates touch and tilt as 0.3.5 does.

Accepted when: every prototype v3 touch area hits within ±4 px in both orientations; no ghost touches during a panel drive; key presses work while the panel is refreshing.

Power and sleep

FR-PWR

Auto-lock after 1, 5 or 15 minutes. Turn off the panel rails, put touch and the tilt sensor to sleep, stop Wi-Fi and enter light sleep. Wake with POWER through the TCA9555 interrupt on GPIO2. Use the P1.3 pulse to power off. Show the gauge reading in the status bar.

Accepted when: 100 sleep and wake cycles all succeed; standby current is measured and written down; charging state is shown correctly on USB.

Storage

FR-STO

4-bit SDMMC mount. Keep the existing dual-slot, CRC-checked record files under .thingsos/. The USB disk uses the HS UTMI PHY and drives ANA_SW low, and reading pauses while it is on.

Accepted when: pulling power during a stats save loses at most one 30-second checkpoint; the USB disk copies 1 GB without corruption.

Network

FR-NET

Station mode with saved networks. The hotspot opens only on the transfer page. The web transfer page, the 微读 client and the network probe are unchanged.

Accepted when: a 50 MB EPUB uploads over Wi-Fi; the 微读 shelf and highlights sync on the real service.

Update and recovery

FR-OTA

16 MB layout: a 2 MiB factory/rescue app, a 10.875 MiB main app and a 3 MiB system font. The rescue app on S31 needs only the hotspot and HTTP OTA. The boot guard switches to rescue on the third failed boot. The web flasher supports S31.

Accepted when: pulling power at five points during an OTA always ends in a bootable device; a deliberately crashing build falls back to rescue; recovery through ROM download mode works.

Frontlight

FR-FL

Two channels, cool and warm, each with brightness in 10 % steps. The reader quick panel and Settings share the same state. The frontlight turns off on lock and is restored on wake.

Accepted when: no visible flicker at any brightness level; the setting survives a reboot.

Architecture

Keep one tree, native/, and split the board layer into one component per device. A Kconfig option THINGSOS_BOARD_READ_PICO / THINGSOS_BOARD_METALIO picks the component, the sdkconfig defaults and the packaging target.

app · native/srcReader, EPUB/TXT/Markdown, layout, graphics, stats, store, 微读, input. Unchanged, and the host tests stay green.
ui · firmware/mainPages and features. Remove the direct BSP calls and route them through board.h.
servicesthingsos_net, thingsos_weidu, OTA and rescue. Change only the PMU and touch calls.
board.hA board-neutral interface with its own thingsos_touch_t, plus new calls for frontlight, haptics and volume keys (stubbed on Read Pico).

§10

Risks

High

The source of the panel VCOM value is unknown. On Read Pico the PMU owns the factory VCOM. On Metalio the TPS65185 register is set by firmware.

Mitigation: get the per-unit VCOM source from Xinzhi before M1, and keep ThingsOS's rule that the factory value is never overwritten.

High

The ESP32-S31 is a new chip. IDF v6.1 support, esptool and esp-web-tools browser flashing may still be immature.

Mitigation: build the S31 rescue app and the web-flasher test in week 1. Keep a USB-serial fallback.

Medium

epdiy has no SIMD path on RISC-V. LUT and packing speed may push page turns past 450 ms.

Mitigation: profile thingsos_panel_pack* on S31 in M1. Optimize the C loops and use row-limited packing.

Medium

The TCA9555 interrupt line is shared with the accelerometer and RTC, which can cause spurious or missed wakes.

Mitigation: read all interrupt sources on wake, and include a wake test in the 100-cycle sleep matrix.

Medium

Hardware revisions V1.3 and V1.4 differ in the XSTL and MODE pins.

Mitigation: detect the revision at boot or make it a build setting. Test on both if possible.

Low

The FT6336U touch firmware upgrade blob ships in the vendor tree.

Mitigation: don't flash touch firmware from ThingsOS. Only read its version.

Low

With a single dev unit there's no spare if the board bricks during bootloader or partition work.

Mitigation: plan for two units, and dump the full flash before the first ThingsOS install.
